# Rabin-Karp String Matching Algorithm
## 1. What is the "Rabin-Karp Algorithm"?

### 1.1 Simple Meaning

The **Rabin-Karp Algorithm** is a string-matching algorithm that finds a **pattern** inside a **text** by converting both the pattern and every window of the text into a **numeric value**, called a **hash value**, using a **hash function**. Instead of comparing strings character by character at every position, it just compares these **numbers** first — which is much faster — and only does a full character-by-character check when two numbers happen to match.

### 1.2 Everyday Analogy

Think of how you might quickly check if two long documents are identical without reading every word: you could first compare their **file sizes**. If the file sizes are different, you instantly know the documents are different, without reading a single word. Only if the file sizes match do you actually open both documents and compare them properly, since two different documents could coincidentally have the exact same file size. A **hash value** works like this "file size" — a quick, cheap number that usually tells two strings apart instantly, with a full character check used only as a final confirmation step.

```
RABIN-KARP — CORE IDEA

  Instead of:  compare text window vs pattern, character by character
               (done at every single shift, every time)

  Rabin-Karp does:  compare HASH(text window) vs HASH(pattern)
                     -> if the numbers are different, SKIP immediately
                     -> if the numbers are the same, THEN do a full
                        character-by-character check, just to be sure
                        (this confirms it isn't a rare coincidence,
                         called a "spurious hit")
```

***

## 2. The Hash Function (Base = 26)

### 2.1 How the Hash Value Is Calculated

Since we are working with the 26 letters of the English alphabet, the hash function in this document always uses **base = 26**. Each letter is first converted into a number:

- For **lowercase** text: `value(c) = c - 'a'`, so `a=0, b=1, c=2, ..., z=25`
- For **uppercase** text: `value(c) = c - 'A'`, so `A=0, B=1, C=2, ..., Z=25`

A string of length `m` is then treated like a number written in **base 26**, exactly the way a normal decimal number is built from digits:

```
hash(s) = ( value(s[0]) * 26^(m-1)
          + value(s[1]) * 26^(m-2)
          + ...
          + value(s[m-1]) * 26^0 )   mod q
```

Here `q` is a chosen **prime number** (we use `q = 101` throughout this document) which keeps the hash values small and reduces the chance of two different strings accidentally producing the same hash (called a **spurious hit**).

### 2.2 The Rolling Hash — Updating Without Recalculating

The real speed advantage of Rabin-Karp comes from **not** recalculating the hash from scratch at every shift. Instead, the hash of the **next** window is calculated from the **previous** window's hash using a simple formula:

```
new_hash = ( 26 * (old_hash - value(text[i]) * h) + value(text[i+m]) )  mod q

where:
  i      = index of the character LEAVING the window (the leftmost old character)
  i+m    = index of the character ENTERING the window (the new rightmost character)
  h      = 26^(m-1) mod q   (precomputed once, used for removing the leftmost character)
```

This means each shift only takes a **constant amount of work** to update the hash, instead of re-reading all `m` characters again.

***

## 3. How It Works — Step by Step

1. Compute the hash of the **pattern**, and the hash of the **first window** of the text (both length `m`), using the formula in Section 2.1.
2. Compare these two hash values.
   - If they are **different**, the pattern definitely does not start here — move on.
   - If they are **the same**, do a **full character-by-character check** to confirm it's a real match and not a spurious hit.
3. Slide the window one position to the right, and update the text's hash value using the **rolling formula** from Section 2.2 (no need to recompute from scratch).
4. Repeat steps 2 and 3 for every possible shift, from `0` to `n - m`.

```
RABIN-KARP — FLOW

   compute patternHash and first textHash
              |
              v
   for shift i = 0 to (n - m):
              |
              v
   is patternHash == textHash ?
        |                  |
       Yes                 No
        |                  |
   do a FULL character   skip straight to
   check to confirm       rolling the hash
   (avoids spurious hit)  forward
        |                  |
        v                  v
   roll the hash forward to the next window
   (using the rolling formula, not from scratch)
              |
              v
    repeat until all shifts are done
```

***

## 4. Time Complexity

| Case | Complexity | When It Happens |
| :-- | :-- | :-- |
| **Average / Best Case** | `O(n + m)` | Hash values rarely collide, so almost no extra character-by-character checks are needed |
| **Worst Case** | `O(n * m)` | Many spurious hits occur (hash values collide often even though the strings differ), forcing a full character check at almost every shift |

Where `n` = length of the text, `m` = length of the pattern. A well-chosen prime `q` keeps spurious hits rare in practice, which is why Rabin-Karp usually performs close to its best case.

## 5. Worked Example 1 — Lowercase Text

**Text:** `"abcabdabc"` (length `n = 9`)
**Pattern:** `"abc"` (length `m = 3`)
**Base = 26**, **q = 101**, using `value(c) = c - 'a'`

### 5.1 Setting Up the Hash Values

`h = 26^(m-1) mod q = 26^2 mod 101 = 676 mod 101 = 70`

**Pattern hash:**
```
hash("abc") = ( value(a)*26^2 + value(b)*26 + value(c) ) mod 101
            = ( 0*676 + 1*26 + 2 ) mod 101
            = 28 mod 101
            = 28
```

### 5.2 Step-by-Step Trace (Rolling Hash)

| Shift `i` | Text Window | Hash Value | Equal to Pattern Hash (28)? | Real Match? |
| :-: | :-- | :-: | :-- | :-- |
| 0 | `abc` | `28` | Yes | Yes -- verified character by character -- **MATCH** |
| 1 | `bca` | `21` | No | -- (skipped, no character check needed) |
| 2 | `cab` | `40` | No | -- |
| 3 | `abd` | `29` | No | -- (close to 28, but still different -- no false alarm here) |
| 4 | `bda` | `47` | No | -- |
| 5 | `dab` | `9` | No | -- |
| 6 | `abc` | `28` | Yes | Yes -- verified character by character -- **MATCH** |

### 5.3 Visualizing Both Matches

```
Index:      0  1  2  3  4  5  6  7  8
Text:      [a  b  c] a  b  d [a  b  c]
Pattern:   [a  b  c]           [a  b  c]
            match #1             match #2
            index 0              index 6
```

### 5.4 Result

**Pattern `"abc"` is found at index `0` and index `6`.** Every intermediate window produced a hash value different from `28`, so no unnecessary character checks were performed except at the two real matches -- this is Rabin-Karp working exactly as intended.

### 5.5 C++ Code for Example 1 (Lowercase)

```cpp
#include <iostream>
#include <string>
using namespace std;

// base value used for the hash function (26, since we are working with
// the 26 letters of the English alphabet)
const int BASE = 26;
// a prime number used as the modulus, to keep hash values small and
// reduce the chance of two different strings getting the same hash
const int MOD = 101;

void rabinKarpSearch(string text, string pattern) {
    int n = text.length();
    int m = pattern.length();

    int patternHash = 0;   // hash value of the pattern
    int textHash = 0;      // hash value of the current window of text
    int h = 1;              // will store BASE^(m-1) % MOD, needed for rolling

    // Precompute h = BASE^(m-1) % MOD
    for (int i = 0; i < m - 1; i++)
        h = (h * BASE) % MOD;

    // Compute the initial hash value of the pattern and of the first
    // window of the text (both of length m)
    for (int i = 0; i < m; i++) {
        patternHash = (patternHash * BASE + (pattern[i] - 'a')) % MOD;
        textHash = (textHash * BASE + (text[i] - 'a')) % MOD;
    }

    // Slide the pattern over the text, one character at a time
    for (int i = 0; i <= n - m; i++) {

        // If the hash values match, it MIGHT be a real match,
        // so we verify character by character to be sure
        // (this guards against rare hash collisions, called "spurious hits")
        if (patternHash == textHash) {
            bool isRealMatch = true;
            for (int j = 0; j < m; j++) {
                if (text[i + j] != pattern[j]) {
                    isRealMatch = false;
                    break;
                }
            }
            if (isRealMatch)
                cout << "Pattern found at index: " << i << endl;
        }

        // Compute the hash of the NEXT window using the rolling formula,
        // instead of recalculating it from scratch
        if (i < n - m) {
            textHash = (BASE * (textHash - (text[i] - 'a') * h) + (text[i + m] - 'a')) % MOD;

            // The % operator in C++ can give a negative result if the
            // value before it was negative, so we correct that here
            if (textHash < 0)
                textHash += MOD;
        }
    }
}

int main() {
    string text = "abcabdabc";
    string pattern = "abc";

    rabinKarpSearch(text, pattern);

    return 0;
}
```

**Verified Output:**
```
Pattern found at index: 0
Pattern found at index: 6
```

This matches exactly what was traced by hand in Section 5.2.

## 6. Worked Example 2 — Uppercase Text

**Text:** `"XYZXYWXYZ"` (length `n = 9`)
**Pattern:** `"XYZ"` (length `m = 3`)
**Base = 26**, **q = 101**, using `value(c) = c - 'A'`

### 6.1 Setting Up the Hash Values

`h = 26^(m-1) mod q = 70` (same as before, since `m` and `q` are unchanged)

`value(X) = 23`, `value(Y) = 24`, `value(Z) = 25`

**Pattern hash:**
```
hash("XYZ") = ( value(X)*26^2 + value(Y)*26 + value(Z) ) mod 101
            = ( 23*676 + 24*26 + 25 ) mod 101
            = ( 15548 + 624 + 25 ) mod 101
            = 16197 mod 101
            = 37
```

### 6.2 Step-by-Step Trace (Rolling Hash)

| Shift `i` | Text Window | Hash Value | Equal to Pattern Hash (37)? | Real Match? |
| :-: | :-- | :-: | :-- | :-- |
| 0 | `XYZ` | `37` | Yes | Yes -- verified character by character -- **MATCH** |
| 1 | `YZX` | `30` | No | -- |
| 2 | `ZXY` | `49` | No | -- |
| 3 | `XYW` | `34` | No | -- (close to 37, but still different -- no false alarm here) |
| 4 | `YWX` | `53` | No | -- |
| 5 | `WXY` | `41` | No | -- |
| 6 | `XYZ` | `37` | Yes | Yes -- verified character by character -- **MATCH** |

### 6.3 Visualizing Both Matches

```
Index:      0  1  2  3  4  5  6  7  8
Text:      [X  Y  Z] X  Y  W [X  Y  Z]
Pattern:   [X  Y  Z]           [X  Y  Z]
            match #1             match #2
            index 0              index 6
```

### 6.4 Result

**Pattern `"XYZ"` is found at index `0` and index `6`.** The same base-26 hashing approach works identically for uppercase text -- the only change needed anywhere in the algorithm is subtracting `'A'` instead of `'a'` when converting a letter into its numeric value.

### 6.5 C++ Code for Example 2 (Uppercase)

```cpp
#include <iostream>
#include <string>
using namespace std;

const int BASE = 26;
const int MOD = 101;

void rabinKarpSearch(string text, string pattern) {
    int n = text.length();
    int m = pattern.length();

    int patternHash = 0;
    int textHash = 0;
    int h = 1;

    for (int i = 0; i < m - 1; i++)
        h = (h * BASE) % MOD;

    // Using 'A' here instead of 'a', since this example works with
    // UPPERCASE letters only -- this is the ONLY change needed
    // compared to the lowercase version in Example 1
    for (int i = 0; i < m; i++) {
        patternHash = (patternHash * BASE + (pattern[i] - 'A')) % MOD;
        textHash = (textHash * BASE + (text[i] - 'A')) % MOD;
    }

    for (int i = 0; i <= n - m; i++) {

        if (patternHash == textHash) {
            bool isRealMatch = true;
            for (int j = 0; j < m; j++) {
                if (text[i + j] != pattern[j]) {
                    isRealMatch = false;
                    break;
                }
            }
            if (isRealMatch)
                cout << "Pattern found at index: " << i << endl;
        }

        if (i < n - m) {
            textHash = (BASE * (textHash - (text[i] - 'A') * h) + (text[i + m] - 'A')) % MOD;
            if (textHash < 0)
                textHash += MOD;
        }
    }
}

int main() {
    string text = "XYZXYWXYZ";
    string pattern = "XYZ";

    rabinKarpSearch(text, pattern);

    return 0;
}
```


## 7. Naive Algorithm vs. Rabin-Karp Algorithm

| Aspect | **Naive String Matching** | **Rabin-Karp Algorithm** |
| :-- | :-- | :-- |
| **What Is Compared at Each Shift** | Every character of the pattern, one by one | A single hash value first; characters only if hashes match |
| **Pre-processing Needed** | None | Compute the pattern's hash and `h = base^(m-1) mod q` once |
| **Updating Between Shifts** | Starts fresh -- no memory of the previous shift | Uses the **rolling hash** formula -- reuses the previous shift's work |
| **Best Case** | `O(n)` | `O(n + m)` |
| **Worst Case** | `O(n * m)` | `O(n * m)` (only if spurious hits happen very often) |
| **Key Idea** | Brute-force character comparison | Fast numeric comparison, with a character check used only as a safety confirmation |

***

## 8. Advantages & Disadvantages

| **Advantages** | **Disadvantages** |
| :-- | :-- |
| Much faster than the Naive Algorithm on average, since most non-matching shifts are skipped using just a number comparison | Still has the same `O(n * m)` worst case as the Naive Algorithm if spurious hits are frequent |
| The **rolling hash** update is a constant-time operation, avoiding repeated re-scanning of the same characters | Requires choosing a good prime modulus `q` -- a poor choice increases the chance of spurious hits |
| Works especially well when searching for **multiple patterns at once** in the same text (by comparing several pattern hashes against one text hash) | Slightly more complex to implement correctly than the Naive Algorithm, due to the modular arithmetic |
