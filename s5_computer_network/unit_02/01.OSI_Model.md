# OSI Model

---

## 1. Introduction to OSI Model

### What is OSI Model

OSI stands for **Open Systems Interconnection**. It is a conceptual, layered reference model developed by ISO (International Organization for Standardization) in 1984 that describes how data communication should take place between two systems, dividing the process into seven distinct layers.

### Key Definition (Quotable)

> "The OSI model is a seven-layer conceptual framework that standardizes the functions of a communication system into distinct layers, allowing different systems to communicate regardless of their underlying architecture."

### Why OSI Model was Developed

- Before OSI, different vendors built proprietary networking systems that could not communicate with each other.
- OSI was designed to promote **interoperability** — allowing hardware and software from different vendors to work together.
- It provides a **standard reference** for understanding, designing, and troubleshooting network systems.
- It breaks a complex process (network communication) into smaller, manageable, independent layers.

### Core Principles Behind Layering

- Each layer performs a specific, well-defined function.
- Each layer communicates only with the layer directly above and below it.
- Each layer on the sender side adds its own header (control information) to the data — this process is called **encapsulation**.
- On the receiver side, each layer removes (strips) the corresponding header — this is called **decapsulation**.
- A change in one layer should not require changes in other layers (this promotes modularity and easier upgrades).

### Exam Points

- OSI is a **reference/conceptual model** — it is not implemented as-is in real networks; TCP/IP is the model actually implemented.
- OSI has exactly **7 layers**; this number itself is a very common one-mark/viva question.
- Remember the mnemonic to recall layer order (bottom to top): **"Please Do Not Throw Sausage Pizza Away"** — Physical, Data Link, Network, Transport, Session, Presentation, Application.

## 2. The Seven Layers of OSI Model (Bottom to Top)

### Overview Table

| Layer No. | Layer Name | PDU (Protocol Data Unit) | Primary Function |
|---|---|---|---|
| 1 | Physical Layer | Bits | Transmission of raw bits over physical medium |
| 2 | Data Link Layer | Frames | Node-to-node delivery, error detection, framing |
| 3 | Network Layer | Packets | Logical addressing and routing between networks |
| 4 | Transport Layer | Segments | End-to-end delivery, reliability, flow/error control |
| 5 | Session Layer | Data | Establishing, managing, and terminating sessions |
| 6 | Presentation Layer | Data | Translation, encryption, compression of data |
| 7 | Application Layer | Data | Interface between network and end-user applications |

---

## 3. Layer 1: Physical Layer

### Function

The Physical Layer is responsible for the actual transmission of raw, unstructured **bits (0s and 1s)** over a physical communication medium (cable, radio wave, etc.).

### Responsibilities

- Defines the physical characteristics of the transmission medium (cables, connectors, voltage levels).
- Defines bit rate — the number of bits transmitted per second.
- Defines the physical topology of the network (bus, star, ring).
- Handles transmission mode (simplex, half-duplex, full-duplex).
- Deals with synchronization of bits between sender and receiver.

### Key Point

The Physical Layer does not understand the meaning of the data — it only deals with the mechanical and electrical transmission of raw bits.

---

## 4. Layer 2: Data Link Layer

### Function

The Data Link Layer is responsible for reliable **node-to-node (hop-to-hop)** delivery of data. It organizes bits received from the Physical Layer into structured units called **frames**.

### Responsibilities

- **Framing**: Divides the stream of bits into manageable units called frames.
- **Physical Addressing**: Adds the sender's and receiver's **MAC address** to each frame.
- **Error Control**: Detects and, in some cases, corrects errors that occur during transmission (e.g., using checksums or CRC).
- **Flow Control**: Ensures a fast sender does not overwhelm a slow receiver.
- **Access Control**: When multiple devices share the same link, determines which device has control over the link at a given time.

### Sub-layers (Additional Exam Detail)

The Data Link Layer is sometimes divided into two sub-layers:

| Sub-layer | Function |
|---|---|
| LLC (Logical Link Control) | Handles flow control and error checking |
| MAC (Media Access Control) | Handles addressing and access to the shared medium |

---

## 5. Layer 3: Network Layer

### Function

The Network Layer is responsible for the delivery of data packets from the **source host to the destination host**, potentially across multiple networks. Its PDU is called a **packet**.

### Responsibilities

- **Logical Addressing**: Adds source and destination **IP addresses** to each packet (detailed in Chapter 3).
- **Routing**: Determines the best path for data to travel from source to destination across interconnected networks.
- **Path Determination**: Uses routing algorithms/protocols to select the optimal path.
- **Fragmentation**: Breaks packets into smaller units if required by the underlying network, and reassembles them at the destination.

### Key Point

While the Data Link Layer handles node-to-node delivery (single link), the Network Layer handles delivery across the **entire path**, potentially involving multiple routers and networks.

---

## 6. Layer 4: Transport Layer

### Function

The Transport Layer is responsible for **end-to-end (process-to-process)** delivery of the entire message, and ensures the message arrives reliably and in the correct order. Its PDU is called a **segment**.

### Responsibilities

- **Segmentation and Reassembly**: Divides the message into segments for transmission, and reassembles them correctly at the destination.
- **Port Addressing**: Adds source and destination **port numbers** to identify the correct process/application on the host.
- **Connection Control**: Provides either connection-oriented (TCP-like) or connectionless (UDP-like) service.
- **Flow Control**: End-to-end flow control (as opposed to node-to-node flow control at the Data Link layer).
- **Error Control**: Ensures the complete message arrives error-free at the destination; may involve retransmission of lost segments.

### Key Point

Transport Layer is often considered the most important layer for reliability, since it is the layer directly responsible for ensuring the message reaches the exact correct application process on the destination machine.

---

## 7. Layer 5: Session Layer

### Function

The Session Layer is responsible for establishing, maintaining, synchronizing, and terminating **sessions** (dialogues) between two communicating applications.

### Responsibilities

- **Session Establishment, Maintenance, Termination**: Manages the start and end of a communication session between two devices.
- **Dialog Control**: Allows communication to happen in half-duplex or full-duplex mode between two systems.
- **Synchronization**: Adds checkpoints (synchronization points) into a stream of data — if a failure occurs, only data after the last checkpoint needs to be retransmitted, not the entire session.

### Example

When you log into a website and stay "logged in" while browsing multiple pages, the session layer concept ensures the continuity of that interaction.

---

## 8. Layer 6: Presentation Layer

### Function

The Presentation Layer acts as a **translator** — it ensures that data sent by the application layer of one system can be read by the application layer of another system, regardless of differences in data representation.

### Responsibilities

- **Translation**: Converts data between different formats (e.g., character encoding differences between sender and receiver systems).
- **Encryption/Decryption**: Ensures data security by encrypting data before transmission and decrypting it at the receiving end.
- **Compression/Decompression**: Reduces the number of bits to be transmitted, improving efficiency, and decompresses at the receiving end.

### Key Point

This layer is also called the **syntax layer**, since it is concerned with the syntax and semantics of the data being exchanged.

---

## 9. Layer 7: Application Layer

### Function

The Application Layer is the topmost layer and serves as the **interface between the end-user application software and the network**. It does not refer to the applications themselves (like a browser), but to the protocols and services that support them.

### Responsibilities

- Provides network services directly to end-user applications (email, file transfer, web browsing).
- Handles user authentication and privacy considerations.
- Provides protocols such as HTTP, FTP, SMTP, DNS.

### Key Point

The Application Layer is the only layer that directly interacts with the end user's software, though it is not the software itself.

---

## 10. Data Encapsulation (How Data Moves Through the Layers)

### Concept

As data moves down the OSI layers on the sender's side, each layer adds its own **header** (and sometimes trailer) containing control information relevant to that layer. This process is called **encapsulation**. On the receiver's side, the reverse process, **decapsulation**, occurs as data moves up the layers, with each layer removing its corresponding header.

### Encapsulation Flow (Sender Side, Top to Bottom)

| Layer | Data Unit After Encapsulation |
|---|---|
| Application/Presentation/Session | Data |
| Transport | Segment (Data + Transport Header) |
| Network | Packet (Segment + Network/IP Header) |
| Data Link | Frame (Packet + Data Link Header and Trailer) |
| Physical | Bits (Frame converted into a bit stream for transmission) |

### Exam Points

- Encapsulation happens on the sender side (top to bottom); decapsulation happens on the receiver side (bottom to top).
- Each layer only adds/removes its own header — it does not alter the headers added by other layers.
- This layered encapsulation is what allows independent, modular development of each layer.
