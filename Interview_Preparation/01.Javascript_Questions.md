# JavaScript Interview Questions & Answers

## Q1. What are the different data types present in JavaScript?

1. **Primitive types** — hold a single value: `String`, `Number`, `BigInt`, `Undefined`, `Null`, `Symbol`
2. **Non-Primitive types** — hold multiple values: `Object`, `Array`, `Function`, `Date`, `Map`, `Set`

---

## Q2. Explain Hoisting in JavaScript.

Hoisting is the default behavior of JavaScript where all variable and function declarations are moved to the top of their scope (local or global) before code execution.

When JavaScript code runs, a **Global Execution Context (GEC)** is created with two phases:
1. **Memory phase** — all variables are initialized as `undefined`, and functions are stored in full.
2. **Execution phase** — code runs line by line.

**Example:**
```js
hoistedVariable = 3;
console.log(hoistedVariable); // outputs 3 even though declared after use
var hoistedVariable;
```

**Note:** Only declarations are hoisted, not initializations.
```js
var x;
console.log(x); // "undefined" — initialization is not hoisted
x = 23;
```

---

## Q3. Difference between `var`, `let`, and `const`.

**`var`:**
- Function-scoped.
- Hoisted to the top of its scope; usable before declaration but value is `undefined` until initialized.
- Re-declaration and re-initialization both possible.
- Stored in the global scope.

**`let`:**
- Block-scoped.
- Re-declaration not possible; re-initialization possible.
- Hoisted but not accessible before declaration (**Temporal Dead Zone**).
- In V8 (Chrome/Node), implementation-wise `let`/`const` are tracked in a separate "script" memory space rather than the global object — but this is an engine implementation detail, not part of the ECMAScript spec. The spec-level fact to lead with is simply: **`let`/`const` are block-scoped and don't become properties of the global object**, unlike `var`.

**`const`:**
- Block-scoped.
- Must be initialized at declaration.
- Hoisted but stays in the TDZ until the declaration line executes.
- Re-declaration not possible.

**Temporal Dead Zone (TDZ):** The time between when a `let`/`const` variable is hoisted and when it is actually initialized with a value.

---

## Q4. Is JavaScript statically typed or dynamically typed?

JavaScript is **dynamically typed** — variable types are checked at runtime, not compile-time, and a variable's type can change at runtime.

## Q5. Explain pass-by-value and pass-by-reference.

JavaScript is technically **always pass-by-value** — but for objects, the "value" being copied is the *reference* (memory address) to the object, not the object itself. This is why it's often loosely described as "primitives are passed by value, objects are passed by reference" — that phrasing is a useful mental model but not 100% precise, and a strict interviewer may probe on this.

**Primitives — a true copy of the value is made:**
```js
var y = 234;
var z = y; // z gets its own separate copy of the value
z = 500;
console.log(y); // 234 (unaffected)
```

**Objects — the reference (address) is copied, so both variables point to the same object:**
```js
var obj = { name: "Vivek", surname: "Bisht" };
var obj2 = obj; // obj2 copies the reference; both point to the same object
obj2.name = "Rahul";
console.log(obj.name); // "Rahul" (same underlying object was mutated)
```

**Key distinction:** if you *reassign* `obj2` entirely (`obj2 = { name: "New" }`), it just points the `obj2` reference elsewhere — `obj` is untouched. Only mutating the object's properties affects both variables.

## Q6. Explain Higher-Order Functions in JavaScript.

Functions that operate on other functions — either by taking them as arguments or by returning them — are called higher-order functions.

## Q7. Explain the `this` keyword.

`this` refers to the object currently executing the function. Its value depends on **how** the function is called, not where it is defined. Arrow functions do not bind their own `this` — using it inside one gives `undefined` (it inherits from the enclosing scope).

---

## Q8. Explain `call()`, `apply()`, and `bind()`.

These methods manually set the value of `this` when calling a function.

- `call()` — invokes immediately, arguments passed individually.
- `apply()` — invokes immediately, arguments passed as an array.
- `bind()` — returns a new function with `this` bound, to be called later.

```js
const person = { name: "Alice" };

function greet(greeting, time) {
  console.log(`${greeting}, ${this.name}. Good ${time}!`);
}

greet.call(person, "Hello", "morning");   // "Hello, Alice. Good morning!"
greet.apply(person, ["Hi", "evening"]);   // "Hi, Alice. Good evening!"

const greetAlice = greet.bind(person, "Hey", "night");
greetAlice();                              // "Hey, Alice. Good night!"
```

---

## Q9. Difference between Arrow functions and Traditional functions.

- Regular function declarations are hoisted and can be called before they appear in code.
- Arrow functions are treated like variables — not callable before definition, due to the TDZ.
- In regular functions, `this` is dynamic (depends on how it's called).
- In arrow functions, `this` is lexical (inherited from where it's written).
- Regular functions can be used as constructors with `new`; arrow functions cannot.

---

## Q10. Difference between function declaration and function expression.

- **Function declaration** — defined using the `function` keyword with a name.
- **Function expression** — a function stored inside a variable.

---

## Q11. What is the event loop in JavaScript?

The event loop handles async operations (`setTimeout`, `fetch`, `Promise`) without blocking execution.

- **Call Stack** — tracks function calls.
- **Callback Queue** — holds `setTimeout`/`setInterval` callbacks.
- **Microtask Queue** — holds promises/`fetch` callbacks (higher priority than the callback queue).

The event loop checks if the call stack is empty, and if so, moves tasks from the microtask queue first, then the callback queue, into the call stack.

---

## Q12. What are Promises in JavaScript?

A **Promise** represents the eventual completion (or failure) of an asynchronous operation.

**States:** `pending`, `fulfilled`, `rejected`
**Key methods:** `.then()`, `.catch()`, `.finally()`

| Method | Behavior |
|---|---|
| `Promise.all([])` | Waits for all to fulfill; rejects immediately if any one rejects |
| `Promise.allSettled([])` | Waits for all to settle; returns status/result for each |
| `Promise.race([])` | Returns the result of the first settled promise |
| `Promise.any([])` | Returns the first *fulfilled* promise; throws `AggregateError` if all reject |

---

## Q13. What is Async/Await in JavaScript?

Async/await handles asynchronous code more readably than raw promises.
- An `async` function always returns a Promise.
- `await` pauses execution inside the async function until the promise resolves.
- Errors are handled with `try...catch`.

---

## Q14. What are Closures?

A closure is a function that remembers variables from its outer (lexical) scope, even after that outer function has finished executing. Real-world analogies: vending machines, ATM machines.

---

## Q15. What is OOP (Object-Oriented Programming)?

OOP is based on classes and objects. Core principles:

- **Encapsulation** — binding data and methods into one unit (object).
- **Abstraction** — hiding internal details, exposing only what's necessary.
- **Inheritance** — a class can inherit properties/methods from another.
- **Polymorphism** — the same method behaves differently depending on the calling object.

## Q16. What are Pure and Impure Functions?

**Pure function** — always returns the same output for the same input, no side effects.
```js
function add(a, b) {
  return a + b;
}
add(2, 3); // always 5
```

**Impure function** — output may vary for the same input, or has side effects.
```js
function getCurrentTime() {
  return new Date(); // depends on external state
}
```

## Q17. What is a Prototype?

Every JavaScript object has an internal link to another object called its **prototype**, used for inheritance. If a property/method isn't found directly on an object, JavaScript looks up the prototype chain.

**`.prototype` vs `__proto__` — these are not the same thing:**
- **`.prototype`** exists only on **constructor functions** (and classes). It's the object that will become the prototype of instances created with `new`.
- **`__proto__`** exists on **instances/objects** themselves, and points back to the prototype object they were created from (i.e., their constructor's `.prototype`).

```js
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  console.log(`Hi, I'm ${this.name}`);
};

const p1 = new Person("Alice");
p1.sayHi(); // "Hi, I'm Alice" — found via the prototype chain

console.log(p1.__proto__ === Person.prototype); // true
```

```js
Array.prototype.sum = function () {
  return this.reduce((acc, val) => acc + val, 0);
};
const nums = [1, 2, 3];
console.log(nums.sum()); // 6
```

- The **prototype chain** lets objects inherit properties/methods from other objects, up to `Object.prototype`, whose own `__proto__` is `null` (end of the chain).
- `__proto__` is a legacy accessor; the modern, recommended way to get/set an object's prototype is `Object.getPrototypeOf()` / `Object.setPrototypeOf()`.

## Q18. What are Memory Leaks in JavaScript?

A memory leak occurs when memory that's no longer needed isn't released. Common causes:
- Global variables not cleared.
- Closures holding references to unused variables.
- Timers and event listeners not cleared (`setInterval`, `addEventListener`).

---

## Q19. What is Garbage Collection in JavaScript?

The automatic process where the JS engine reclaims memory by removing objects that are no longer reachable, using the **mark-and-sweep** algorithm.

---

## Q20. Difference between Stack and Heap.

- **Stack** — static memory; stores primitives, function calls, reference addresses.
- **Heap** — dynamic memory; stores objects, arrays, closures.

---

## Q21. What are Dynamic Imports?

Dynamic imports (`import()`) allow modules to be loaded at runtime, enabling lazy loading.

## Q22. What is Currying?

A functional programming technique where a function with multiple arguments is transformed into a series of functions that each take one argument.

```js
// Without currying
function add(a, b) { return a + b; }
add(2, 3); // 5

// With currying
function add(a) {
  return function (b) {
    return a + b;
  };
}
add(2)(3); // 5
```

---

## Q23. What is Debouncing?

Ensures a function runs only after a certain delay since the last time it was invoked. Useful for search-input auto-suggestions.

```js
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
```

---

## Q24. What is Throttling?

Ensures a function is called at most once every specified interval, even if triggered multiple times.

```js
function sendingMessage(query) {
  console.log('Sending message...', query);
}

function throttle(fn, delay) {
  let lastCall = 0;
  return function (...args) {
    let now = Date.now();
    if (now - lastCall < delay) return;
    lastCall = now;
    return fn(...args);
  };
}

const sendingMessageThrottle = throttle(sendingMessage, 2000);
sendingMessageThrottle('hi');
sendingMessageThrottle('Hello');
sendingMessageThrottle('Hello Vikas');
```

---

## Q25. What is Memoization?

An optimization technique that caches the results of expensive function calls, so future calls with the same arguments return the cached result instantly.

## Q26. What is Event Delegation?

A technique where a single event listener is added to a parent element to handle events from its child elements, using event bubbling.

## Q27. What is the DOM?

The **DOM (Document Object Model)** is a programming interface for HTML/XML documents, representing the page as a tree of objects accessible via JavaScript.

- **Methods:** `getElementById`, `querySelector`, etc.
- **Events:** `click`, `submit`, `keydown`, etc.
- **Structure modification:** `createElement`, `appendChild`, etc.

## Q28. What is the BOM?

The **BOM (Browser Object Model)** provides access to browser-specific features outside the HTML document — the browser environment around the DOM. Examples: `alert`, `location`, `navigator`, `history`.

## Q29. What is Event Bubbling and Capturing?

- **Bubbling** — events propagate from child to parent.
- **Capturing** — events propagate from parent to child.

## Q30. What is the use of `Object.freeze()` and `Object.seal()`?

- **`Object.freeze()`** — makes an object fully immutable.
- **`Object.seal()`** — prevents adding/removing properties, but allows modifying existing ones.

## Q31. Difference between `map`, `filter`, and `reduce`.

- **`map()`** — transforms each element, returns a new array of the same length.
- **`filter()`** — returns a new array containing only elements that pass a condition.
- **`reduce()`** — reduces the array to a single accumulated value.

---

## Q32. What is Event Propagation in JavaScript?

The process by which events move through the DOM tree when triggered. Three phases:

1. **Capturing phase** — event travels from root (window/document) down to the target.
2. **Target phase** — event reaches the actual target element.
3. **Bubbling phase** — event bubbles back up from the target to the root.

---

## Q33. What is a Polyfill in JavaScript?

A polyfill provides modern functionality on older browsers that don't natively support it, "filling in" the missing feature.

```js
if (!Array.prototype.includes) {
  Array.prototype.includes = function (element) {
    return this.indexOf(element) !== -1;
  };
}
```

## Q34. Difference between `==` and `===`.

- `==` (loose equality) compares values **after** type coercion.
- `===` (strict equality) compares both value **and** type, with no coercion.

```js
0 == '0';    // true  (coerced)
0 === '0';   // false (different types)
null == undefined;   // true
null === undefined;  // false
```

Best practice: prefer `===` to avoid unexpected coercion bugs.

---

## Q35. Difference between `typeof` and `instanceof`.

- **`typeof`** — returns a string indicating the primitive type of a value. Works for primitives, but for objects/arrays it just returns `"object"`.
- **`instanceof`** — checks whether an object is an instance of a specific constructor/class, by walking the prototype chain.

```js
typeof "hello";        // "string"
typeof 42;              // "number"
typeof {};               // "object"
typeof [];               // "object" (not "array"!)

[] instanceof Array;    // true
[] instanceof Object;   // true
```

---

## Q36. Difference between `null` and `undefined`.

- **`undefined`** — a variable has been declared but not assigned a value; also the default return value of functions with no return statement.
- **`null`** — an intentional absence of any value, explicitly assigned by the developer.

```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null

typeof undefined; // "undefined"
typeof null;      // "object" (a long-standing JS quirk)
```

## Q37. What are Destructuring, Spread, and Rest?

**Destructuring** — unpack values from arrays/objects into variables.
```js
const [a, b] = [1, 2];
const { name, age } = { name: "Sam", age: 25 };
```

**Spread (`...`)** — expands an iterable into individual elements.
```js
const arr1 = [1, 2];
const arr2 = [...arr1, 3, 4]; // [1, 2, 3, 4]

const obj1 = { x: 1 };
const obj2 = { ...obj1, y: 2 }; // { x: 1, y: 2 }
```

**Rest (`...`)** — collects remaining elements/arguments into an array.
```js
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3); // 6
```

## Q38. What are Template Literals?

String literals that allow embedded expressions and multi-line strings, using backticks.

```js
const name = "Alice";

```

## Q39. What is Optional Chaining (`?.`) and Nullish Coalescing (`??`)?

**Optional chaining (`?.`)** — safely access nested properties without throwing an error if an intermediate value is `null`/`undefined`.
```js
const city = user?.address?.city; // undefined instead of throwing
```

**Nullish coalescing (`??`)** — returns the right-hand value only if the left is `null` or `undefined` (unlike `||`, which also triggers on `0`, `''`, `false`).
```js
const count = 0;
count || 10;  // 10 (wrong if 0 is a valid value)
count ?? 10;  // 0  (correct — 0 is not nullish)
```

## Q40. What are Generators and Iterators?

**Iterator** — an object implementing the iterator protocol, with a `next()` method returning `{ value, done }`.

**Generator** — a special function (`function*`) that can pause and resume execution using `yield`, automatically producing an iterator.

```js
function* counter() {
  yield 1;
  yield 2;
  yield 3;
}

const gen = counter();
gen.next(); // { value: 1, done: false }
gen.next(); // { value: 2, done: false }
gen.next(); // { value: 3, done: false }
gen.next(); // { value: undefined, done: true }
```

`Symbol.iterator` is the well-known symbol that makes an object iterable (usable in `for...of`, spread, etc.).

---

## Q41. Difference between `Map`/`Set` and `WeakMap`/`WeakSet`.

- **`Map`** — key-value pairs, keys can be any type, iterable, keeps strong references (prevents garbage collection).
- **`Set`** — collection of unique values, iterable.
- **`WeakMap`** — keys must be objects, held with **weak references** (allows garbage collection), not iterable.
- **`WeakSet`** — like `Set` but only stores objects weakly, not iterable.

Weak versions are useful for storing metadata about objects without preventing those objects from being garbage collected.

---

## Q42. What are Proxy and Reflect?

**`Proxy`** — wraps an object and lets you intercept and customize fundamental operations (get, set, delete, etc.) via "traps."

```js
const handler = {
  get(target, prop) {
    return prop in target ? target[prop] : `Property "${prop}" not found`;
  }
};
const p = new Proxy({ name: "Alice" }, handler);
console.log(p.name); // "Alice"
console.log(p.age);  // 'Property "age" not found'
```

**`Reflect`** — a built-in object providing methods that mirror the Proxy traps (`Reflect.get`, `Reflect.set`, etc.), used to perform the default operation from inside a trap.

## Q44. Difference between Shallow Copy and Deep Copy.

- **Shallow copy** — copies only the top-level properties; nested objects are still shared by reference.
- **Deep copy** — recursively copies all nested levels, so the copy is fully independent.

```js
const obj = { a: 1, nested: { b: 2 } };

// Shallow copy
const shallow = { ...obj };
shallow.nested.b = 99;
console.log(obj.nested.b); // 99 (shared reference)

// Deep copy
const deep = structuredClone(obj);
deep.nested.b = 42;
console.log(obj.nested.b); // still 99 (independent)
```

`structuredClone()` is the modern built-in way to deep clone. Older approaches use `JSON.parse(JSON.stringify(obj))` (loses functions, `undefined`, `Date` objects, etc.) or libraries like Lodash's `cloneDeep`.

## Q45. What is an IIFE (Immediately Invoked Function Expression)?

A function that runs as soon as it's defined, used to create an isolated scope and avoid polluting the global namespace.

```js
(function () {
  var secret = "hidden";
  console.log("IIFE ran");
})();
```

## Q46. What is Strict Mode?

`'use strict'` enables a restricted variant of JavaScript that catches common mistakes: prevents accidental globals, throws errors on invalid assignments, disallows duplicate parameter names, and makes `this` `undefined` in standalone functions instead of defaulting to the global object.

```js
'use strict';
x = 10; // ReferenceError: x is not defined
```

## Q47. What is Callback Hell and how does async/await solve it?

**Callback hell** is deeply nested callbacks that make code hard to read and maintain, often called the "pyramid of doom."

```js
getUser(id, (user) => {
  getPosts(user.id, (posts) => {
    getComments(posts[0].id, (comments) => {
      console.log(comments);
    });
  });
});
```

Promises and `async/await` flatten this into sequential, readable code:

```js
async function getData() {
  const user = await getUser(id);
  const posts = await getPosts(user.id);
  const comments = await getComments(posts[0].id);
  console.log(comments);
}
```

## Q49. Difference between `fetch` and `XMLHttpRequest`; what is CORS?

**`fetch`** — modern, Promise-based API for making HTTP requests; cleaner syntax than `XMLHttpRequest`.
**`XMLHttpRequest`** — older, callback/event-based API, more verbose but supports some features `fetch` doesn't natively (like upload progress tracking).

**CORS (Cross-Origin Resource Sharing)** — a browser security mechanism that restricts web pages from making requests to a different origin (domain/port/protocol) than the one that served the page, unless the server explicitly allows it via response headers like `Access-Control-Allow-Origin`.

## Q50. What are common JavaScript design patterns?

- **Module pattern** — encapsulates private state/behavior using closures, exposing a public API.
- **Singleton pattern** — ensures only one instance of an object exists.
- **Observer pattern** — an object (subject) maintains a list of dependents (observers) and notifies them of state changes (basis of event systems, pub/sub).
- **Factory pattern** — a function that creates and returns objects without exposing the instantiation logic directly.

---

## Q51. What is XSS and CSRF?

**XSS (Cross-Site Scripting)** — an attacker injects malicious scripts into a trusted website, which then execute in other users' browsers. Prevented by sanitizing/escaping user input and using Content Security Policy (CSP).

**CSRF (Cross-Site Request Forgery)** — an attacker tricks a logged-in user's browser into making an unwanted request to a site where they're authenticated. Prevented using CSRF tokens and `SameSite` cookie attributes.
