# React Interview Questions & Answers

## Q1. What is React?

It's a library for building user interfaces. It's known for its component-based architecture and allows us to create reusable UI elements.

---

## Q2. What is declarative vs imperative programming?

- **Imperative** — we give detailed information on *how* to do something; we care about the process.
  *Example:* doubling each element of an array using a `for` loop.
- **Declarative** — we just specify *what* we want; we don't care about the process, only the output.
  *Example:* doubling each element using `.map()`.

---

## Q3. What is Client-Side Rendering (CSR) and Server-Side Rendering (SSR)?

- **CSR** — the browser downloads a minimal HTML page and a JS bundle; content is rendered in the browser using JavaScript.
- **SSR** — content is rendered on the server, and a fully rendered HTML page is sent to the browser.

**When to use:**
- **CSR** — apps with heavy user interaction (dashboards, admin panels) where SEO isn't a top concern.
- **SSR** — SEO-sensitive pages (blogs, landing pages).

---

## Q4. What is a Single Page Application (SPA)?

An SPA is a web application that loads a single HTML page and dynamically updates content without reloading the entire page as the user navigates between sections.

---

## Q5. What is a CDN?

A **CDN (Content Delivery Network)** is a network of servers distributed globally that deliver web content (images, videos, CSS, JS, HTML) from the server nearest to the user, making websites faster and more reliable.

---

## Q6. Difference between Virtual DOM and Actual DOM.

- **Actual DOM** — the real structure of HTML elements rendered by the browser. Changes trigger reflow/repaint, which can be slow with frequent or complex updates.
- **Virtual DOM** — a lightweight in-memory copy of the Actual DOM. When component state changes, React updates the Virtual DOM first, compares it against the previous version via **diffing**, and applies only the minimum necessary changes to the Actual DOM.
- The Virtual DOM exists only in memory — it's not directly visible to the user.

---

## Q7. What is Axios?

Axios is a promise-based HTTP client for making HTTP requests (GET, POST, PUT, DELETE). It provides automatic JSON parsing, easy error handling, and support for interceptors.

---

## Q8. What is a Component?

A component acts like a JavaScript function but returns JSX (HTML-like code). It's a reusable, independent piece of UI.

---

## Q9. What are Props?

Props are read-only data passed from a parent component to a child component, used to make components reusable and dynamic.

---

## Q10. What are Hooks?

Hooks are utilities that let you "hook onto" React's features (state, lifecycle, context, etc.) from functional components.

---

## Q11. What is `useState`?

`useState` is a Hook that lets you create state variables in functional components. It returns the current state and a function to update it. Whenever the state changes, React automatically re-renders the component with the new value.

---

## Q12. What is `useEffect`?

`useEffect` is a Hook that lets you perform "side effects" in functional components — data fetching, timers (`setTimeout`, `setInterval`), subscriptions, etc.

```js
useEffect(() => {
  // first: side-effect function

  return () => {
    // second: clean-up function
  }
}, [/* third: dependency list */])
```

**Variations:**

```js
// Runs on every render
useEffect(() => { })

// Runs only on first render
useEffect(() => { }, [])

// Runs whenever `count` changes
useEffect(() => { }, [count])

// Runs whenever `count` OR `total` changes
useEffect(() => { }, [count, total])

// Cleanup runs on unmount
useEffect(() => {
  return () => {
    alert('count is unmounted from UI');
  }
}, [count])
```

**Counter example using `useEffect`:**
```jsx
const [count, setCount] = useState(0);

useEffect(() => {
  if (count >= 10) return;
  const timer = setTimeout(() => {
    setCount(count + 1);
  }, 1000);
  return () => {
    clearTimeout(timer);
  }
}, [count]);

return (
  <div>
    <p>Count: {count}</p>
  </div>
);
```

**Dependency array behavior:**
- **Empty array `[]`** — runs only once, on initial render.
- **Has values `[x]`** — runs initially, and again whenever `x` changes.
- **No dependency array** — runs on every render.

## Q13. What is `useContext`?

`useContext` provides a way to pass data through the component tree (nested components) without manually passing props at every level — useful for things like theming.

---

## Q14. What is Routing in React?

Routing enables navigation between different components based on the URL, typically using the `react-router-dom` library (must be installed separately).

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/about" element={<About />} />
  </Routes>
</BrowserRouter>
```

- Using an `<a>` tag causes a full page refresh on navigation.
- Using `<Link>` navigates without refreshing the page.
- `<NavLink>` works like `<Link>` but attaches an `active` class automatically, making it easy to style the currently active link.

**Child (nested) routes:**
```jsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route path="profile" element={<Profile />} />
  <Route path="settings" element={<Settings />} />
</Route>
```
The parent layout component must include `<Outlet />` where the matched child route should render.

Use a `*` path to catch all unmatched routes (404 handling).


## Q16. What is `useNavigate`?

A hook used to programmatically navigate between pages/routes (e.g., redirecting after a form submission), instead of relying on `<Link>` clicks.

## Q17. What is Redux?

Redux is a state management library used to manage and centralize application state predictably — for any given input (state + action), you always get the same output.

---

## Q18. What is a Pure Function?

A pure function always returns the same result when given the same arguments, and has no side effects.

---

## Q19. What is an Action in Redux?

An action is a plain object with a `type` field (and optionally a `payload`). The `type` describes what kind of state change should occur.

---

## Q20. What is a Reducer in Redux?

A reducer is a pure function that takes the current state and an action as arguments, and returns a new state.

```js
const initialState = { count: 0 };

function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { count: state.count + 1 };
    case 'DECREMENT':
      return { count: state.count - 1 };
    default:
      return state;
  }
}
```

---

## Q21. What is a Slice in Redux?

A **slice** (from Redux Toolkit) is a collection of reducer logic and actions for a single feature/domain of state, created using `createSlice()`. It bundles together the initial state, the reducer functions, and auto-generated action creators — removing the need to hand-write action types and switch-based reducers separately.

```js
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { count: 0 },
  reducers: {
    increment: (state) => { state.count += 1; },  // Immer lets you "mutate" directly
    decrement: (state) => { state.count -= 1; },
  },
});

export const { increment, decrement } = counterSlice.actions;
export default counterSlice.reducer;
```

This is now the standard, recommended way to write Redux logic (via Redux Toolkit), replacing the older manual `switch`-based reducer + separate action creator pattern.

## Q22. What is the Store in Redux?

The Redux store is a centralized object holding the entire application state. It allows you to:
- Store the state
- Dispatch actions
- Subscribe to changes
- Get the current state

---

## Q23. What is State in Redux?

State is a plain JavaScript object holding the entire application's data, managed centrally in the Redux store.

---

## Q24. What is Middleware in Redux?

Middleware is a function that sits between `dispatch()` and the reducer, letting you intercept actions, run custom logic (like logging or async calls), and then pass the action along (or not) to the reducer.

---

## Q25. What is `useSelector`?

*(Note: the original notes had an incorrect description here, mixing this up with middleware — corrected below.)*

`useSelector` is a hook that lets a component read/extract specific pieces of data from the Redux store's state, without needing `connect()` or manual subscriptions. It does **not** intercept actions or add custom logic — that's what middleware does.

```js
const count = useSelector((state) => state.counter.count);
```

---

## Q26. What is `useDispatch`?

A hook used to get the `dispatch` function, which is used to send (dispatch) actions to the Redux store.

```js
const dispatch = useDispatch();
dispatch({ type: 'INCREMENT' });
```

---

## Q27. What is `useMemo`?

`useMemo` is a Hook that memoizes (caches) the result of a calculation, recomputing it only when its dependencies change — useful for optimizing expensive computations.

```js
const squaredNumber = useMemo(() => {
  console.log("Calculating square...");
  return number * number;
}, [number]);
```

---

## Q28. What is `useCallback`?

`useCallback` memoizes a *function* itself, so it isn't re-created on every render unless its dependencies change — useful for avoiding unnecessary re-renders of child components that receive the function as a prop.

---

## Q29. What is Lazy Loading?

Lazy loading means loading components only when they're needed, rather than all at once — improving performance and reducing initial bundle size.

```js
// ES6 Module
const Component = React.lazy(() => import('./Component'));
```

Any lazily-loaded component must be wrapped in `<Suspense>`:
```jsx
<Suspense fallback={<div>Loading...</div>}>
  <Component />
</Suspense>
```

## Q30. What is Debouncing?

A technique to limit how often a function executes. It ensures the function runs only once after a specified delay, and only if no new event occurred during that delay. Common use case: search input.

```js
function search(query) {
  console.log('Searching for...', query);
}

function debounce(search, delay) {
  let timerId;
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(function () {
      search(...args);
    }, delay);
  }
}

const debounceFunction = debounce(search, 1000);
debounceFunction('H');
debounceFunction('Hi');
debounceFunction('Hi V');
debounceFunction('Hi Vikas');
// Only the final call ("Hi Vikas") actually triggers `search`, after the delay
```

## Q31. Difference between Controlled and Uncontrolled Components.

- **Controlled component** — form data is handled by React state; the input's value is driven by state, and changes go through an `onChange` handler.
- **Uncontrolled component** — form data is handled by the DOM itself; you access the value using a `ref` instead of state.

```jsx
// Controlled
function ControlledInput() {
  const [value, setValue] = useState("");
  return <input value={value} onChange={(e) => setValue(e.target.value)} />;
}

// Uncontrolled
function UncontrolledInput() {
  const inputRef = useRef(null);
  const handleSubmit = () => console.log(inputRef.current.value);
  return <input ref={inputRef} />;
}
```

Controlled components are generally preferred in React for predictability and easier validation; uncontrolled components are handy for simple forms or integrating with non-React code.

## Q32. What is `React.memo`?

A higher-order component that memoizes a functional component, skipping re-renders if its props haven't changed (shallow comparison). Useful for optimizing performance in components that render often with the same props.

```jsx
const MyComponent = React.memo(function MyComponent({ value }) {
  console.log("Rendered");
  return <div>{value}</div>;
});
```

You can pass a custom comparison function as a second argument for more control over when it re-renders.

## Q33. What is `useRef`?

A Hook that returns a mutable ref object whose `.current` property persists across renders without causing a re-render when it changes. Common uses:
- Accessing/manipulating a DOM element directly (e.g., focusing an input).
- Storing a mutable value (like a timer ID) that shouldn't trigger a re-render when updated.

```jsx
function TextInput() {
  const inputRef = useRef(null);
  const focusInput = () => inputRef.current.focus();
  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}
```

## Q34. What is `useReducer`?

A Hook used for more complex state logic than `useState` easily handles — especially when the next state depends on the previous one, or state has multiple sub-values. Works similarly to Redux reducers.

```jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    default: throw new Error();
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <>
      <p>{state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>-</button>
    </>
  );
}
```

## Q35. What are Custom Hooks?

A custom hook is a JavaScript function whose name starts with `use` and that can call other hooks inside it — used to extract and reuse stateful logic across multiple components.

```js
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);
  return width;
}

// Usage
function Component() {
  const width = useWindowWidth();
  return <p>Window width: {width}</p>;
}
```

## Q36. What is Prop Drilling, and what is a Higher-Order Component (HOC)?

**Prop drilling** — passing data through several layers of intermediate components that don't need the data themselves, just to get it to a deeply nested child. Solved using `useContext`, Redux, or other state management.

**Higher-Order Component (HOC)** — a function that takes a component and returns a new, enhanced component, used to reuse component logic (similar in spirit to custom hooks, but at the component level rather than the hook level).

```js
function withLogger(WrappedComponent) {
  return function (props) {
    console.log("Rendering with props:", props);
    return <WrappedComponent {...props} />;
  };
}

const EnhancedComponent = withLogger(MyComponent);
```

## Q37. What are Error Boundaries and `React.StrictMode`?

**Error Boundary** — a class component that implements `componentDidCatch()` (and/or `static getDerivedStateFromError()`) to catch JavaScript errors in its child component tree, log them, and display a fallback UI instead of crashing the whole app. (There is no Hook-based equivalent yet — error boundaries must be class components.)

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  componentDidCatch(error, info) {
    console.error(error, info);
  }
  render() {
    if (this.state.hasError) return <h1>Something went wrong.</h1>;
    return this.props.children;
  }
}
```

**`React.StrictMode`** — a development-only wrapper component that helps identify potential problems (deprecated APIs, unsafe lifecycle methods, unexpected side effects) by intentionally double-invoking certain functions in development. It has no effect in production builds.

## Q38. Why are Keys Important in Lists?

Keys help React identify which items in a list have changed, been added, or removed, so it can update the DOM efficiently during reconciliation instead of re-rendering the entire list.

```jsx
{items.map((item) => (
  <li key={item.id}>{item.name}</li>
))}
```

**Common mistake:** using the array index as the key. This can cause bugs (wrong item state carried over, unnecessary re-renders) if the list is reordered, filtered, or items are inserted/removed — because React matches by position, not identity. Prefer a stable, unique identifier (like a database ID) instead.

## Q39. What are Class Components and Lifecycle Methods?

Before Hooks, class components were the primary way to manage state and lifecycle in React.

```jsx
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
  }
  componentDidMount() {
    console.log("Mounted");
  }
  componentDidUpdate(prevProps, prevState) {
    console.log("Updated");
  }
  componentWillUnmount() {
    console.log("Unmounting");
  }
  render() {
    return <p>{this.state.count}</p>;
  }
}
```

**Common lifecycle methods and their Hook equivalents:**

| Class lifecycle | Hook equivalent |
|---|---|
| `componentDidMount` | `useEffect(() => {}, [])` |
| `componentDidUpdate` | `useEffect(() => {}, [dep])` |
| `componentWillUnmount` | cleanup function returned from `useEffect` |

Still commonly asked in interviews even though functional components + Hooks are now the standard.

## Q40. What is Reconciliation in React?

Reconciliation is the algorithm React uses to compare (diff) the new Virtual DOM tree against the previous one and determine the minimal set of changes needed to update the Actual DOM.

Key rules React uses to make this efficient:
- Elements of **different types** (e.g., `<div>` → `<span>`) cause React to tear down the old tree and build a new one from scratch.
- Elements of the **same type** are compared attribute-by-attribute, and only the differences are applied.
- **Keys** in lists let React match children across renders, avoiding unnecessary re-creation of DOM nodes.

React's diffing is a heuristic O(n) algorithm rather than the theoretically optimal O(n³) tree-diff, trading some precision for speed.

## Q41. What's new in React 18? (Concurrent Rendering, Automatic Batching, `useTransition`)

- **Concurrent Rendering** — React can prepare multiple versions of the UI at once and interrupt/pause rendering work to keep the app responsive (e.g., prioritizing user input over a large re-render).
- **Automatic Batching** — in React 18, state updates are batched (grouped into a single re-render) even inside promises, `setTimeout`, and native event handlers — not just inside React event handlers as before.
- **`useTransition`** — lets you mark certain state updates as non-urgent ("transitions"), so React can keep the UI responsive while that update is processed in the background.

```jsx
const [isPending, startTransition] = useTransition();

function handleChange(e) {
  const value = e.target.value;
  setInput(value); // urgent — update immediately
  startTransition(() => {
    setSearchResults(filterResults(value)); // non-urgent — can be deferred
  });
}
```

## Q42. Redux Toolkit vs Classic Redux.

**Classic Redux** required a lot of boilerplate:
- Manually written action types and action creators.
- Manually written `switch`-based reducers.
- Manual store setup, often with middleware configured by hand.
- Immutability had to be handled manually (spreading objects/arrays).

**Redux Toolkit (RTK)** — the officially recommended approach — simplifies this:
- `createSlice()` bundles reducers, actions, and initial state together (see Q21).
- Uses **Immer** internally, so you can write "mutating" code that's actually converted to immutable updates safely.
- `configureStore()` sets up the store with good defaults (including Redux DevTools and common middleware) automatically.
- `createAsyncThunk()` simplifies handling async logic (like API calls) with built-in pending/fulfilled/rejected action types.

```js
export const fetchUser = createAsyncThunk('user/fetch', async (userId) => {
  const response = await fetch(`/api/users/${userId}`);
  return response.json();
});
```

## Q43. What are `forwardRef` and Portals?

**`forwardRef`** — lets a component pass a `ref` it receives down to one of its child DOM elements, useful for reusable component libraries where the parent needs direct access to an inner DOM node.

```jsx
const FancyInput = React.forwardRef((props, ref) => (
  <input ref={ref} className="fancy" {...props} />
));

// Usage: parent can now do inputRef.current.focus()
const inputRef = useRef(null);
<FancyInput ref={inputRef} />
```

**Portals** — let you render a child component into a DOM node that exists outside its parent component's DOM hierarchy, while still preserving its place in the React component tree (for events, context, etc.). Commonly used for modals, tooltips, and dropdowns that need to escape a parent's `overflow: hidden` or `z-index` stacking context.

```jsx
ReactDOM.createPortal(
  <Modal />,
  document.getElementById('modal-root')
);
```

## Q44. What are the basics of Testing in React (Jest & React Testing Library)?

- **Jest** — a JavaScript testing framework used to run tests, make assertions, and mock functions/modules.
- **React Testing Library (RTL)** — a library for testing React components by interacting with them the way a user would (querying by text, role, label), rather than testing internal implementation details.

```jsx
import { render, screen, fireEvent } from '@testing-library/react';
import Counter from './Counter';

test('increments count on button click', () => {
  render(<Counter />);
  const button = screen.getByText('Increment');
  fireEvent.click(button);
  expect(screen.getByText('Count: 1')).toBeInTheDocument();
});
```

RTL's guiding philosophy: *"The more your tests resemble the way your software is used, the more confidence they can give you."*
