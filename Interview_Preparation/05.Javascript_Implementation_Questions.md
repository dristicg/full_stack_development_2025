### 1. Reverse a string

**What to build:** A function that takes a string and returns it backwards.

**Rules:**
- Do it without `.reverse()` first, using a loop.
- Then show the one-line version using `split`, `reverse`, `join`.
- Handle an empty string (return empty string).

**Example:**
```js
reverseString("hello")   // "olleh"
reverseString("")        // ""
```

**Topics to learn first:**
- `for` loops and string indexing (`str[i]`)
- String concatenation with `+`
- `split()`, `reverse()`, `join()`

### 2. Check if a string is a palindrome 

**What to build:** A function that returns `true` if a word reads the same forwards and backwards.

**Rules:**
- Ignore uppercase/lowercase — "Racecar" is a palindrome.
- Ignore spaces and punctuation — "A man, a plan, a canal: Panama" is a palindrome.
- Use two pointers (one from the start, one from the end) instead of reversing the whole string.

**Example:**
```js
isPalindrome("Racecar")                        // true
isPalindrome("A man, a plan, a canal: Panama") // true
isPalindrome("hello")                          // false
```

**Topics to learn first:**
- `toLowerCase()`
- Regular expressions to remove non-letters: `str.replace(/[^a-z0-9]/gi, "")`
- Two-pointer technique (a `left` index and a `right` index moving toward each other)

### 4. Find the largest and second largest number in an array 

**What to build:** Return the biggest and the second biggest number.

**Rules:**
- Do it in **one pass** (one loop), not by sorting.
- Handle duplicates: in `[5, 5, 3]` the second largest is `3`, not `5`.
- Return `null` for second largest if the array has fewer than 2 distinct numbers.

**Example:**

**Topics to learn first:**

### 15. `debounce(fn, delay)` 

**What it does:** Waits until the user **stops** doing something, then runs your function once.

**Real example:** A search box. The user types "laptop" — 6 letters. Without debounce you send 6 API
calls. With debounce you send 1 call, after they stop typing.

**What to build:**
- `debounce(fn, delay)` returns a **new function**.
- Each time the new function is called, cancel the old timer and start a fresh one.
- When a timer completes without being cancelled, call `fn`.
- Pass all arguments through to `fn`.

**Example:**
```js
const search = debounce(q => console.log("searching", q), 500);
search("l"); search("la"); search("lap");
// only "searching lap" runs, 500ms after the last call
```

**Topics to learn first:**
- **Closures** — how the returned function still remembers the `timer` variable
- `setTimeout` and `clearTimeout`
- Rest parameters `(...args)` and `fn.apply(this, args)`
- Why you use `function` and not an arrow function here (so `this` works correctly)

**Once it works, add:** a `.cancel()` method that throws away the pending call.

### 16. `throttle(fn, limit)` 

**What it does:** Runs your function **at most once every X milliseconds**, even if it's called 100
times in that period.

**Real example:** A scroll handler. Scrolling fires hundreds of events per second. Throttle limits
it to one check every 200ms.

**What to build:**
- Remember the time of the last run.
- On each call, if `now - lastRun >= limit`, run `fn` and update `lastRun`.
- Otherwise, ignore the call.

**Example:**
```js
const onScroll = throttle(() => console.log("scrolled"), 1000);
// called 50 times in 3 seconds → runs about 3 times
```

**Topics to learn first:**
- `Date.now()` for timestamps
- Closures for keeping `lastRun` between calls
- The difference from debounce (interviewers always ask):
  - **Debounce** = wait for quiet, then run once → search boxes, auto-save
  - **Throttle** = run at a steady maximum rate → scroll, resize, mousemove

### 17. Write your own `map`, `filter` and `forEach` 

**What to build:** Add `myMap`, `myFilter` and `myForEach` to `Array.prototype` so they work like
the real ones.

**Rules:**
- Inside the method, `this` is the array.
- The callback receives three things: `(element, index, wholeArray)`.
- `myMap` returns a **new** array of the same length.
- `myFilter` returns a **new** array with only the items where the callback returned true.
- `myForEach` returns `undefined`.
- Do not use the real `map`/`filter` inside your version.

**Example:**
```js
[1, 2, 3].myMap(x => x * 2)        // [2, 4, 6]
[1, 2, 3].myFilter(x => x > 1)     // [2, 3]
```

**Topics to learn first:**
- `Array.prototype` — where array methods actually live
- `this` inside a prototype method
- The full callback signature `(el, i, arr)` — freshers usually forget `i` and `arr`

### 18. Write your own `reduce` 

**What to build:** `myReduce(callback, initialValue)` that folds an array into a single value.

**Rules (this is where people fail):**
- The callback gets `(accumulator, element, index, array)`.
- If `initialValue` is given → start with it, and begin the loop at index 0.
- If `initialValue` is **not** given → use the first element as the starting value, and begin the
  loop at index **1**.
- If the array is empty **and** there is no `initialValue` → throw
  `TypeError("Reduce of empty array with no initial value")`.

**Example (verified behaviour of the real method):**
```js
[1,2,3].reduce((a,b) => a+b)      // 6
[1,2,3].reduce((a,b) => a+b, 10)  // 16
[].reduce((a,b) => a+b)           // TypeError: Reduce of empty array with no initial value
[].reduce((a,b) => a+b, 0)        // 0
```

**Topics to learn first:**
- The accumulator pattern
- `arguments.length` to detect whether a parameter was actually passed
- Throwing errors: `throw new TypeError("...")`

### 19. Write your own `call`, `apply` and `bind` 

**What they do:** All three let you decide what `this` will be inside a function.

**What to build:**

`myCall(thisArg, ...args)`
- Temporarily attach the function as a property of `thisArg`
- Call it so `this` becomes `thisArg`
- Delete the temporary property and return the result
- Use a `Symbol` as the property name so you never overwrite a real property

`myApply(thisArg, argsArray)`
- Same as `myCall`, but arguments arrive as one array

`myBind(thisArg, ...presetArgs)`
- Returns a **new function** that is permanently locked to `thisArg`
- Preset arguments come first, later arguments are added after

**Example:**
```js
function greet(greeting, mark) { return greeting + " " + this.name + mark; }
const user = { name: "Vikas" };

greet.myCall(user, "Hi", "!")        // "Hi Vikas!"
greet.myApply(user, ["Hi", "!"])     // "Hi Vikas!"
const hi = greet.myBind(user, "Hi");
hi("!")                              // "Hi Vikas!"
```

**Topics to learn first:**
- The four ways `this` gets its value (default, object method, explicit call/apply/bind, `new`)
- `Symbol` — a unique key that can never clash
- Closures for `bind`
- Dot notation vs bracket notation for object properties

### 20. `deepClone(obj)` 

**What to build:** A copy of a nested object where changing the copy never affects the original.

**Rules:**
- Handle nested objects and arrays using recursion.
- Return primitives (numbers, strings, booleans, `null`) as they are.
- Handle `Date` (return a new `Date`) and arrays (return a new array).
- **Bonus:** handle circular references (an object that points back to itself) using a `WeakMap` —
  without it your function crashes with "Maximum call stack size exceeded".

**Example:**
```js
const a = { name: "X", tags: ["a"], meta: { active: true } };
const b = deepClone(a);
b.meta.active = false;
a.meta.active;   // still true 
```

**Topics to learn first:**
- Recursion
- `typeof` and `Array.isArray` for type checking
- `WeakMap` (a Map whose keys are objects, used here to remember what you already copied)
- Why `JSON.parse(JSON.stringify(x))` is not enough

### 21. `deepEqual(a, b)`

**What to build:** Return `true` if two values have the same structure and same values.

**Rules:**
- Primitives: compare directly.
- Objects: compare the **number of keys first**, then compare each key recursively.
- Arrays: compare length, then each element.
- Return `false` if one is `null` and the other is an object.

**Example:**
```js
deepEqual({a: 1, b: {c: 2}}, {a: 1, b: {c: 2}})   // true
deepEqual({a: 1}, {a: 1, b: 2})                   // false
deepEqual([1, [2]], [1, [2]])                     // true
```

**Topics to learn first:**
- Recursion
- `Object.keys(obj).length`
- `typeof null === "object"` — a classic JavaScript trap you must handle

### 22. `curry(fn)` 

**What it does:** Turns `add(1, 2, 3)` into `add(1)(2)(3)` — you can pass arguments a few at a time.

**What to build:**
- `curry(fn)` returns a function.
- Each time it's called, collect the arguments.
- Once you have as many arguments as the original function expects, run it.
- Otherwise, return another function that waits for more.

**How do you know how many it expects?** `fn.length` gives the number of declared parameters.

**Example:**
```js
function add(a, b, c) { return a + b + c; }
const curried = curry(add);

curried(1)(2)(3)     // 6
curried(1, 2)(3)     // 6
curried(1)(2, 3)     // 6
```

**Topics to learn first:**
- Closures
- `fn.length` (arity = how many parameters a function declares)
- Recursion
- Rest/spread and `fn.apply`

### 24. `memoize(fn)` 

**What it does:** Remembers the result of a function so repeated calls with the same input are
instant instead of recomputed.

**What to build:**
- Keep a cache (a `Map` or plain object) inside a closure.
- Build a key from the arguments (`JSON.stringify(args)` works for simple cases).
- If the key exists in the cache, return the stored value.
- Otherwise run `fn`, store the result, and return it.

**Example:**
```js
const slowSquare = n => { for(let i=0;i<1e8;i++){} return n*n; };
const fast = memoize(slowSquare);
fast(5);   // slow the first time
fast(5);   // instant — came from cache
```

**Topics to learn first:**
- Closures for private cache storage
- `Map` vs plain object as a cache
- Why a cache key matters, and why `JSON.stringify` breaks for functions or key order

### 27. `get(obj, "a.b.c", defaultValue)`

**What it does:** Safely read a deeply nested value without crashing when something in the middle
is missing.

**Real example:** `user.address.city` crashes if `address` is `undefined`. `get(user, "address.city", "N/A")`
returns `"N/A"` instead.

**What to build:**
- Split the path string on `.` (and handle `[0]` for arrays).
- Walk down the object one key at a time.
- If any step is `null` or `undefined`, stop and return the default value.
- Never throw an error.

**Example:**
```js
const user = { profile: { social: { twitter: "@vikas" } } };
get(user, "profile.social.twitter")          // "@vikas"
get(user, "profile.social.github", "none")   // "none"
get(user, "a.b.c.d.e", null)                 // null (no crash)
```

**Topics to learn first:**
- `split(".")` and looping over path parts
- Optional chaining `?.` (the modern built-in alternative)
- Nullish checks (`== null` catches both `null` and `undefined`)

### 29. `EventEmitter` class

**What it is:** The publish/subscribe pattern — one part of your app announces something happened,
and other parts listen for it.

**What to build a class with:**
- `on(event, handler)` — register a listener
- `off(event, handler)` — remove a listener
- `once(event, handler)` — run a listener only the first time, then auto-remove it
- `emit(event, ...args)` — call every listener registered for that event

**Rules:**
- Store listeners in an object or `Map`: `{ eventName: [handler1, handler2] }`.
- `emit` should loop over a **copy** of the array, so a handler that removes itself doesn't break
  the loop.
- `on` should return an unsubscribe function (nice touch interviewers like).

**Example:**
```js
const bus = new EventEmitter();
bus.on("login", user => console.log("Welcome", user));
bus.emit("login", "Vikas");   // "Welcome Vikas"
```

**Topics to learn first:**
- Classes, `constructor`, and methods
- Objects/`Map` holding arrays of functions
- `filter` or `indexOf` + `splice` for removing a listener
- Closures for the `once` wrapper

# Promises & async

### 30. `promisify(fn)`

**What it does:** Converts an old-style callback function into one that returns a Promise, so you
can use `await` with it.

**Background:** Node's old style is `fn(args, (error, result) => {})` — the error comes first.

**What to build:**
- Return a new function.
- Inside, return a `new Promise`.
- Call the original function, adding your own callback.
- In that callback: if `error` exists → `reject(error)`, otherwise → `resolve(result)`.

**Example:**
```js
const readFileAsync = promisify(fs.readFile);
const data = await readFileAsync("file.txt", "utf8");
```

**Topics to learn first:**
- The Promise constructor: `new Promise((resolve, reject) => {})`
- Error-first callback convention
- Closures and rest parameters

---

### 31. `sleep(ms)` and `retry(fn, times, delay)`

**What to build two things:**

`sleep(ms)` — returns a Promise that resolves after `ms`, so `await sleep(1000)` pauses your code.

`retry(fn, times, delay)` — calls an async function, and if it fails, tries again:
- Try up to `times` times.
- Wait between attempts, increasing the wait each time (**exponential backoff**: 1s, 2s, 4s…).
- If all attempts fail, reject with the last error.

**Why backoff matters:** if a server is down and 1,000 clients all retry every second, you make the
problem worse. Increasing delays give the server room to recover.

**Example:**
```js
await sleep(1000);
const data = await retry(() => fetch("/api/data"), 3, 1000);
```

**Topics to learn first:**
- `async`/`await` inside a `for` loop
- `try...catch` around `await`
- The Promise constructor with `setTimeout`
- Exponential backoff (`delay * 2 ** attempt`)

---

### 32. `timeout(promise, ms)`

**What to build:** Wrap a Promise so it rejects if it takes longer than `ms`.

**Rules:**
- Use `Promise.race` between the original promise and a timer that rejects.
- Clear the timer when the original finishes first, so it doesn't keep running.

**Example:**
```js
await timeout(fetch("/slow-api"), 3000);   // rejects after 3s if not finished
```

**Topics to learn first:**
- `Promise.race` (settles with whichever finishes first)
- `setTimeout` / `clearTimeout`
- Creating custom errors: `new Error("Request timed out")`

### 33. Write your own `Promise.all` 

**What it does:** Takes an array of promises, waits for all of them, and gives you an array of
results **in the original order**.

**Rules:**
- Results must be in **input order**, not completion order — this is the part people get wrong.
- Keep a counter of how many have finished; only resolve when the counter equals the array length.
- If any promise rejects, reject immediately with that error (fail fast).
- An empty array resolves immediately with `[]`.
- Values that aren't promises should be treated as already-resolved.

**Example:**
```js
myPromiseAll([Promise.resolve(1), 2, slowPromise(3)])
// resolves with [1, 2, 3] — in this order, even if slowPromise finishes last
```

**Topics to learn first:**
- Promise constructor
- Storing results by index: `results[i] = value`
- A completion counter
- `Promise.resolve(value)` to normalise non-promise values

### 34. Write `Promise.allSettled`, `Promise.race` and `Promise.any`

**What each one does:**

| Method | Resolves when | Rejects when |
|---|---|---|
| `all` | all succeed | any one fails |
| `allSettled` | all finish (success or failure) | never rejects |
| `race` | the first one finishes, either way | if the first one to finish failed |
| `any` | the first **success** | only if every single one fails |

**Rules:**
- `allSettled` returns objects: `{ status: "fulfilled", value }` or `{ status: "rejected", reason }`.
- `any` rejects with an `AggregateError` containing all the errors.

**Example:**
```js
await myAllSettled([Promise.resolve(1), Promise.reject("err")])
// [{ status: "fulfilled", value: 1 }, { status: "rejected", reason: "err" }]
```

**Topics to learn first:**
- The difference between "settled", "fulfilled" and "rejected"
- Counters and result arrays
- `AggregateError`

### 35. Run promises with a concurrency limit

**What to build:** `mapLimit(items, limit, asyncFn)` — process 100 items but never more than
`limit` at the same time.

**Real example:** Uploading 100 images. Firing all 100 at once crashes the browser or gets you rate
limited. Running them 5 at a time is safe.

**Rules:**
- Start `limit` tasks immediately.
- As soon as one finishes, start the next waiting item (do **not** wait for the whole batch).
- Keep the results in the original order.

**Example:**
```js
await mapLimit(imageUrls, 5, url => upload(url));
// never more than 5 uploads running at once
```

**Topics to learn first:**
- `async`/`await`
- A "worker pool" idea: run N loops that each pull the next index from a shared counter
- Storing results by index to keep order

### 36. Fix a race condition in a search box

**The bug:** The user types "ab" then "abc". The "ab" request is slower and arrives **after** the
"abc" request. Now the screen shows results for "ab" while the box says "abc".

**What to build:** A search function where a stale (older) response can never overwrite a newer one.

**Two ways to fix it:**
1. Keep a counter/id for each request and ignore the response if a newer request has started.
2. Use `AbortController` to cancel the previous request when a new one starts.

**Example:**
```js
const controller = new AbortController();
fetch(url, { signal: controller.signal });
controller.abort();   // cancels the previous request
```

**Topics to learn first:**
- `AbortController` and `AbortSignal`
- Why responses can arrive out of order
- Catching `AbortError` separately from real errors

### 37. Predict the output — event loop

**What to do:** For each snippet, write the output order on paper **before** running it, then run it
and check. The answers below are verified.

**Snippet A:**
```js
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
queueMicrotask(() => console.log('4'));
(async () => { console.log('5'); await null; console.log('6'); })();
console.log('7');
```
**Answer: `1, 5, 7, 3, 4, 6, 2`**

Why:
- `1`, `5`, `7` run first because they are normal synchronous code (`5` runs because the async
  function body runs immediately until it hits `await`).
- `3`, `4`, `6` are **microtasks** — they run next, in the order they were queued. The code after
  `await` becomes a microtask.
- `2` is a **macrotask** (`setTimeout`) and always runs after all microtasks are finished.

**Snippet B:**
```js
async function g() { console.log('c'); }
async function f() { console.log('a'); await g(); console.log('b'); }
f(); console.log('d');
```
**Answer: `a, c, d, b`**

Why: `f()` runs `a`, then calls `g()` which runs `c` immediately. The `await` pauses `f`, so `d`
runs next, and `b` runs last as a microtask.

**Snippet C (Node only):**
```js
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
setTimeout(() => console.log('setTimeout'), 0);
setImmediate(() => console.log('setImmediate'));
```
**Answer: `nextTick, promise`, then `setTimeout` and `setImmediate` in an order that is not
guaranteed from the main module.** `process.nextTick` always beats promises; both always beat timers.

**Topics to learn first:**
- Call stack → microtask queue → macrotask queue
- `await` is really `.then()` on the rest of the function
- `process.nextTick` has higher priority than promises (Node only)

### 38. Closures — the `var` in a loop trap 

**The problem:**
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// prints 3, 3, 3  — not 0, 1, 2
```

**Why:** `var` creates **one** shared variable for the whole loop. By the time the timers run, the
loop has finished and `i` is 3. A closure remembers the *variable*, not the value it had at the time.

**What to build:** Fix it three ways:
1. Change `var` to `let` — `let` creates a new binding for each iteration.
2. Wrap it in an IIFE that captures the current value as a parameter.
3. Pass `i` as an extra argument to `setTimeout`.

**Topics to learn first:**
- Function scope (`var`) vs block scope (`let` / `const`)
- Closures capture variables, not values
- IIFE (Immediately Invoked Function Expression)

### 39. `this` — fix the lost context bug 

**The problem:**
```js
class Counter {
  count = 0;
  increment() { this.count++; }
}
const c = new Counter();
button.addEventListener("click", c.increment);   //  "Cannot read properties of undefined"
```

**Why:** When you pass `c.increment` as a value, it loses its connection to `c`. `this` is decided
by **how a function is called**, not where it was written.

**What to build:** Fix it three ways:
1. Arrow function at the call site: `() => c.increment()`
2. `.bind(c)` in the constructor
3. Define the method as a class field arrow function: `increment = () => { this.count++ }`

**Topics to learn first:**
- The four rules for `this`: default, object method, explicit (`call`/`apply`/`bind`), and `new`
- Arrow functions take `this` from where they were **written**, not how they're called
- Class fields
