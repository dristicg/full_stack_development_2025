# Informed Search Techniques

***

## 1. What is "Informed Search Technique"?

### Simple Meaning

An **Informed Search** (also called **Heuristic Search**) is a search strategy that uses **extra domain-specific knowledge** — called a **heuristic function `h(n)`** — to make a smart *guess* about how close a given state is to the goal. Unlike uninformed search (BFS, DFS, UCS), which blindly explores based only on the problem definition, informed search uses this "hint" to **prioritize exploring the most promising states first**, making it dramatically faster in large search spaces.

**In the simplest words:** If Uninformed Search is exploring a building with the **lights off**, Informed Search is exploring the **same building with a floor map and "warmer/colder" signs** pointing roughly toward the exit — you still have to walk the corridors yourself, but you now know *roughly which direction* to try first.

```
UNINFORMED SEARCH
(no idea where the goal is)

   ┌─────────────────────┐
   │  ?    ?    ?    ?   │
   │  ?    ?    ?    ?   │
   │  ?    ?    ?  [GOAL]│
   └─────────────────────┘

   Must check states almost randomly —
   no sense of "direction"

──────────────────────────────

INFORMED SEARCH
(has an ESTIMATE of distance to goal)

   ┌─────────────────────┐
   │ "6"   "2"   "8"  "1"│
   │ "4"   "5"   "3"  "7"│
   │ "9"   "6"   "0" GOAL│
   └─────────────────────┘

   h(n) estimates shown at each node —
   can head toward the LOWEST estimate
   first, far fewer wasted explorations
```

### The Heuristic Function `h(n)`

The **heuristic function `h(n)`** is simply a number representing the **estimated cost from state `n` to the nearest goal state** — it is *not* the actual, guaranteed cost, just an informed guess based on domain knowledge.

**Everyday Analogy:** When driving, the **straight-line ("as the crow flies") distance** to your destination shown on a map is a heuristic. It's not the *real* driving distance (roads curve, there's traffic), but it gives you a very useful **estimate** to judge which direction is roughly closer.

## 2. Uninformed vs. Informed Search — Detailed Comparison

### The Core Difference, in Simple Words

**Uninformed Search** decides what to explore next using only what it can directly observe from the problem itself — the number of steps taken (BFS), the order of discovery (DFS), or the actual accumulated cost so far (UCS). **Informed Search** additionally uses a **heuristic estimate of remaining distance to the goal**, letting it "look ahead" (in a rough, estimated sense) before actually exploring.

```
DECISION-MAKING: WHAT DOES EACH STRATEGY LOOK AT?
──────────────────────────────────────────────────

UNINFORMED SEARCH
  BFS  →  looks at: depth/level only
  DFS  →  looks at: which branch first
  UCS  →  looks at: g(n), cost-so-far only

INFORMED SEARCH
  Greedy Best-First  →  looks at: h(n) only
  A*                 →  looks at: g(n) + h(n)
                         (both actual cost AND
                          estimated remaining cost)
```

### Detailed Comparison Table

| Aspect | Uninformed Search (Blind) | Informed Search (Heuristic) |
| :-- | :-- | :-- |
| **Extra Knowledge Used** | None — only what's inside the problem definition (states, actions, goal test) | Uses a **heuristic function `h(n)`** — an estimate of distance/cost remaining to the goal |
| **"Sense of Direction"** | None — explores blindly (level-by-level, branch-by-branch, or by cost-so-far) | Yes — actively prioritizes states that *seem* closer to the goal |
| **Speed / Efficiency** | Usually slower — may explore many irrelevant states before reaching the goal | Usually much faster — skips large portions of the search space that are clearly unpromising |
| **Examples** | BFS, DFS, Uniform Cost Search (UCS) | Greedy Best-First Search, A\* Search |
| **Guaranteed Optimal?** | UCS and BFS (equal costs) — yes; DFS — no | A\* — yes (**if** the heuristic is *admissible*, i.e., never overestimates); Greedy Best-First — **no guarantee** |
| **Real-World Feel** | Wandering a maze with the lights off | Wandering the same maze with a rough "warmer/colder" hint at every junction |
| **Main Weakness** | Can be very slow on large search spaces — wastes time exploring clearly bad options | Entirely depends on the **quality of the heuristic** — a bad or misleading heuristic can hurt performance or even correctness |

### Why This Matters

- Uninformed search techniques **guarantee correctness** through brute-force thoroughness, but this doesn't scale well — real-world problems (like chess, or route-finding across an entire country) have **far too many states** to explore blindly in reasonable time.
- Informed search doesn't remove the need to search — it simply uses **domain knowledge (the heuristic)** to search *smarter*, exploring the most promising options first. This is the foundation of nearly all practical, large-scale AI search systems used today (GPS routing, game-playing AI, robotics path planning).

## 3. Two Key Algorithms in Informed Search

Informed search is built almost entirely around two foundational algorithms, both of which we'll explain in full depth below:

```
1. GREEDY BEST-FIRST SEARCH
   ──────────────────────────
   Decision based ONLY on:

        h(n)
   (estimated cost to the goal)

   ⚡ Very fast, but
      NOT guaranteed optimal


2. A* SEARCH
   ──────────────────────────
   Decision based on BOTH:

        g(n)   +   h(n)
   (actual cost        (estimated cost
    so far, from        to the goal,
    UCS)                 same as Greedy)

   ⚖ Balances speed AND correctness —
     guaranteed optimal (with a good
     heuristic)
```

**In one line:** Greedy Best-First Search is "fast but reckless" (only cares about what *looks* closest to the goal), while A\* is "fast *and* careful" (combines the real cost paid so far with the estimate of what's left) — which is exactly why A\* is one of the most widely used search algorithms in all of AI.

## 4. Greedy Best-First Search

### What is Greedy Best-First Search?

**Greedy Best-First Search** is an informed search algorithm that always expands the node that **appears closest to the goal**, based purely on the heuristic value `h(n)` — it completely **ignores** how much cost has already been spent getting there (`g(n)`). It uses a **Priority Queue (Min-Heap)**, ordered only by `h(n)`.

**In the simplest words:** It's "greedy" because at every step, it simply asks *"Which option looks closest to the finish line right now?"* and picks that one — without ever considering *"but how far have I already had to travel to get here?"*

**Everyday Analogy:** Imagine hiking toward a mountain peak you can **see in the distance**. At every fork in the trail, you always take whichever path *looks* like it's pointing most directly at the peak — even if that path is actually steep, rocky, and exhausting. You might reach the peak, but not necessarily by the easiest or shortest actual route, because you never stopped to weigh how much effort you'd already spent.

***

### How Greedy Best-First Search Works — Step by Step

1. Put the **start state** into a Priority Queue, ordered by its heuristic value `h(start)`.
2. Repeat until the Priority Queue is empty:
   a. **Remove** the state with the **lowest `h(n)`** from the Priority Queue.
   b. If it's the **goal**, stop — a solution is found (**not guaranteed to be the cheapest one!**).
   c. Otherwise, add all its **unvisited neighbours** to the Priority Queue, each ordered by *their own* `h(n)` value.
3. If the Priority Queue becomes empty without finding the goal, no solution exists.

***

### Key Properties of Greedy Best-First Search

| Property | Greedy Best-First Search Behaviour |
| :-- | :-- |
| **Data Structure Used** | Priority Queue (Min-Heap), ordered **only** by heuristic value `h(n)` |
| **Completeness** | Not guaranteed in general (can loop or get stuck in infinite spaces); guaranteed in small finite spaces |
| **Optimality** | **No** — does **not** guarantee the lowest-cost path, since actual cost `g(n)` is completely ignored |
| **Time Complexity** | O(b^m) in the worst case — where *b* = branching factor, *m* = maximum depth (can be much better with a good heuristic) |
| **Space Complexity** | O(b^m) — must store generated nodes in the Priority Queue |
| **Main Risk** | A misleading heuristic can send it down a very expensive path, purely because that path *looked* closer to the goal at each individual step |

***

### Worked Example — Where Greedy Best-First Search Goes Wrong

**Problem:** Find a path from `S` (start) to `G` (goal). Numbers on the arrows are the **actual cost** `g(n)` of that action. The `h(n)` value beside each node is the heuristic's **estimated cost remaining to reach `G`**.

```
GRAPH: arrow labels = actual edge cost g(n)
h(n) = heuristic estimate to reach Goal G

              1                5
        S ─────────▶ A ─────────▶ G
        │                         ▲
        │                         │
        │        4                │ 1
        └──────────────▶ B ───────┘

HEURISTIC VALUES (estimated distance remaining to reach G):

   h(S) = 3      h(A) = 0
   h(B) = 1      h(G) = 0

   Note: h(A) = 0 misleadingly looks
   "right next to the goal"
```

Notice the **true, actual costs** of the two possible routes:
- `S → A → G` = actual cost `1 + 5` = **6**
- `S → B → G` = actual cost `4 + 1` = **5**  ← this is genuinely the cheaper route

But Greedy Best-First Search never looks at actual cost — only at `h(n)`. Here is exactly what it does:

| Step | Node Expanded | h(n) | Frontier (Priority Queue, ordered by h only) After This Step |
| :-- | :-- | :-- | :-- |
| 1 | *(start)* | — | `[ (h=3, S) ]` |
| 2 | **S** | 3 | `[ (h=0, A), (h=1, B) ]` |
| 3 | **A** (lowest h = 0) | 0 | `[ (h=0, G), (h=1, B) ]` ← A's only neighbour, G, is pushed |
| 4 | **G** (lowest h = 0) | 0 |  **Goal popped — STOP (Greedy never even looks at B!)** |

```
RESULT

  Path Found:    S → A → G
  Actual Cost:   1 + 5 = 6      ❌ NOT the cheapest path
  Cheaper path S → B → G (cost 5) was NEVER explored,
  because B's heuristic (h=1) looked slightly "further"
  than A's heuristic (h=0) — even though B was actually
  the better choice once real cost is considered.
```

**The key lesson:** Greedy Best-First Search found *a* solution quickly, but not the **best** one — this exact weakness (ignoring cost already spent) is precisely what the next algorithm, **A\***, is designed to fix.

***

### C++ Implementation of Greedy Best-First Search

```cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

typedef pair<int, int> pii; // {heuristic value h(n), node}

class Graph {
    int numVertices;
    vector<vector<pii>> adjList; // adjList[u] = list of {neighbour, edgeCost}
    vector<int> heuristic;       // heuristic[node] = h(n)

public:
    Graph(int vertices) {
        numVertices = vertices;
        adjList.resize(vertices);
        heuristic.resize(vertices);
    }

    void addEdge(int u, int v, int cost) {
        adjList[u].push_back({v, cost});
    }

    void setHeuristic(int node, int h) {
        heuristic[node] = h;
    }

    // Greedy Best-First Search from 'start' to 'goal'
    void greedyBestFirstSearch(int start, int goal) {
        priority_queue<pii, vector<pii>, greater<pii>> pq; // min-heap by h(n)
        vector<bool> visited(numVertices, false);

        pq.push({heuristic[start], start});

        while (!pq.empty()) {
            auto [hValue, current] = pq.top();
            pq.pop();

            if (visited[current]) continue;
            visited[current] = true;

            cout << "Expanding node: " << current << " (h = " << hValue << ")" << endl;

            if (current == goal) {
                cout << "Goal reached! (Note: Greedy does NOT guarantee lowest actual cost)" << endl;
                return;
            }

            for (auto &[neighbour, cost] : adjList[current]) {
                if (!visited[neighbour]) {
                    pq.push({heuristic[neighbour], neighbour});
                }
            }
        }
        cout << "Goal not reachable." << endl;
    }
};

int main() {
    // Nodes: 0 = S, 1 = A, 2 = B, 3 = G
    Graph g(4);
    g.addEdge(0, 1, 1);  // S -> A, actual cost 1
    g.addEdge(0, 2, 4);  // S -> B, actual cost 4
    g.addEdge(1, 3, 5);  // A -> G, actual cost 5
    g.addEdge(2, 3, 1);  // B -> G, actual cost 1

    g.setHeuristic(0, 3); // h(S) = 3
    g.setHeuristic(1, 0); // h(A) = 0
    g.setHeuristic(2, 1); // h(B) = 1
    g.setHeuristic(3, 0); // h(G) = 0

    g.greedyBestFirstSearch(0, 3); // Start S(0), Goal G(3)
    return 0;
}
```

**Expected Output:**
```
Expanding node: 0 (h = 3)
Expanding node: 1 (h = 0)
Expanding node: 3 (h = 0)
Goal reached! (Note: Greedy does NOT guarantee lowest actual cost)
```

This matches the hand trace exactly: it expands `S → A → G` (nodes 0 → 1 → 3), never even touching node `B` — confirming it finds a valid but **not the cheapest** path.

***

### Real-Life Example 1: Simple GPS "Direction Guessing" (Without Traffic/Distance Awareness)

A very basic navigation tool that always picks the next road segment simply pointing most directly toward the destination's compass direction (ignoring actual road length or traffic) behaves like Greedy Best-First Search — it can be led down a road that "looks right" but turns out to be a long detour, while a slightly "less direct-looking" road would have actually been shorter.

### Real-Life Example 2: Web Crawlers Prioritizing "Promising-Looking" Pages

A basic web crawler trying to find a specific topic might prioritize links whose **anchor text looks most relevant** (a heuristic) to the topic, diving into those pages first — without any concept of "how many pages it has already crawled to get here." This can make it fast at finding *a* relevant page, but not necessarily via the most efficient crawl path.

## 5. A* Search Algorithm

### What is A\* Search?

**A\* (pronounced "A-star") Search** is an informed search algorithm that combines the best of **both worlds**: it uses `g(n)`, the **actual cost from the start to node `n`** (exactly like Uniform Cost Search), **plus** `h(n)`, the **heuristic estimate from `n` to the goal** (exactly like Greedy Best-First Search). It always expands the node with the **lowest total `f(n) = g(n) + h(n)`**.

```
        f(n)   =   g(n)   +   h(n)

  g(n)  = ACTUAL cost already paid
          (this is what UCS uses)
          "How far have I already come?"

  h(n)  = ESTIMATED cost still remaining
          (this is what Greedy uses)
          "How far do I still have to go?"
```

**In the simplest words:** A\* asks a smarter question at every step: *"Considering both what I've already spent AND my best estimate of what's left, which option gives the best total deal?"* — this is exactly what prevents it from being fooled the way Greedy Best-First Search was.

**Everyday Analogy:** Going back to the mountain-hiking analogy: A\* is like a hiker who, at every fork, considers **both** how much effort they've already spent climbing to this point **and** their best estimate of the remaining distance to the peak — instead of just chasing whichever path looks closest to the peak *right now*. This balanced thinking is exactly why A\* reliably finds the truly best route.

***

### The Condition for A\* to Guarantee the Optimal Path: Admissible Heuristic

A\* is only **guaranteed** to find the optimal (cheapest) path if its heuristic is **admissible** — meaning `h(n)` must **never overestimate** the true remaining cost to the goal (it can underestimate, or be exactly right, but never claim something is "further" than it truly is).

**Everyday Analogy:** An admissible heuristic is like a slightly **optimistic** friend giving you travel-time estimates — they might say "should take about 10 minutes" for a trip that actually takes 12 (underestimating is fine), but they should never say "30 minutes" for a trip that actually only takes 12 (overestimating misleads you into skipping a genuinely good route).

***

### How A\* Search Works — Step by Step

1. Put the **start state** into a Priority Queue, with `f(start) = g(start) + h(start)`, where `g(start) = 0`.
2. Repeat until the Priority Queue is empty:
   a. **Remove** the state with the **lowest `f(n)`** from the Priority Queue.
   b. If it's the **goal**, stop — this is guaranteed to be the **optimal path** (assuming an admissible heuristic)!
   c. Otherwise, for each neighbour, calculate `g(neighbour) = g(current) + edge cost`, then `f(neighbour) = g(neighbour) + h(neighbour)`. If this is a cheaper `g` value than any previously found for that neighbour, push/update it in the Priority Queue.
3. If the Priority Queue becomes empty without finding the goal, no solution exists.

***

### Key Properties of A\* Search

| Property | A\* Search Behaviour |
| :-- | :-- |
| **Data Structure Used** | Priority Queue (Min-Heap), ordered by `f(n) = g(n) + h(n)` |
| **Completeness** | Yes — guaranteed to find a solution if one exists (assuming finite branching and positive edge costs) |
| **Optimality** | **Yes** — guaranteed to find the lowest-cost path, **as long as the heuristic is admissible** |
| **Time Complexity** | Highly dependent on the **quality of the heuristic** — a very accurate heuristic makes A\* extremely fast; a poor one makes it behave closer to UCS |
| **Space Complexity** | Can be high — like UCS, it must store all generated frontier nodes (this is A\*'s main practical limitation on very large problems) |
| **Relationship to Other Algorithms** | If `h(n) = 0` for every node, A\* becomes **exactly** Uniform Cost Search; if `g(n)` is ignored entirely, it becomes Greedy Best-First Search — A\* is genuinely the "combination" of both |

***

### Worked Example — A\* Correctly Fixing Greedy's Mistake

We reuse the **exact same graph and heuristic values** as the Greedy Best-First Search example above, so we can directly compare the two algorithms on identical data.

```
GRAPH: arrow labels = actual edge cost g(n)
h(n) = heuristic estimate to reach Goal G

              1                5
        S ─────────▶ A ─────────▶ G
        │                         ▲
        │                         │
        │        4                │ 1
        └──────────────▶ B ───────┘

HEURISTIC VALUES:
   h(S) = 3      h(A) = 0
   h(B) = 1      h(G) = 0
```

**Step-by-step trace (Priority Queue, ordered by lowest `f(n) = g(n) + h(n)` first):**

| Step | Node Expanded | g(n) | h(n) | f(n) = g+h | Frontier After This Step |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | *(start)* | — | — | — | `[ (f=3, S) ]`  *(g=0, h=3)* |
| 2 | **S** | 0 | 3 | 3 | `[ (f=1, A), (f=5, B) ]` ← A: g=0+1=1, f=1+0=1  •  B: g=0+4=4, f=4+1=5 |
| 3 | **A** (lowest f = 1) | 1 | 0 | 1 | `[ (f=5, B), (f=6, G) ]` ← G via A: g=1+5=6, f=6+0=6 |
| 4 | **B** (lowest f = 5) | 4 | 1 | 5 | `[ (f=5, G), (f=6, G) ]` ← G via B: g=4+1=5, f=5+0=5 (**cheaper — replaces/beats the earlier one!**) |
| 5 | **G** (lowest f = 5) | 5 | 0 | 5 |  **Goal popped with f = 5 → STOP, this is optimal!** |

```
FINAL RESULT

  ✅ Path Found:  S → B → G
  ✅ Total Cost:  4 + 1 = 5          (the TRUE optimal path)
  ❌ NOT chosen:  S → A → G  (cost 6 — the path Greedy Best-First
                              incorrectly settled for, now correctly avoided)
```

**Why this proves A\* is optimal here:** Even though node `A` had a very tempting `h(A) = 0` and got expanded first, A\* did **not** stop there — because reaching `G` *through* `A` still totals `f = 6` once its real cost `g = 6` is included. A\* only accepts the goal once it is popped as the entry with the **lowest total `f(n)`** in the whole frontier — and that only happened via the `S → B → G` route, with `f = 5`. This is exactly how combining `g(n)` and `h(n)` protects A\* from the mistake Greedy Best-First Search made.

***

### C++ Implementation of A\* Search

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <climits>
using namespace std;

struct Node {
    int vertex;
    int gCost; // actual cost from start to this node
    int fCost; // gCost + heuristic
};

struct Compare {
    bool operator()(const Node &a, const Node &b) {
        return a.fCost > b.fCost; // min-heap: smallest f(n) has highest priority
    }
};

class Graph {
    int numVertices;
    vector<vector<pair<int, int>>> adjList; // adjList[u] = list of {neighbour, edgeCost}
    vector<int> heuristic;                  // heuristic[node] = h(n)

public:
    Graph(int vertices) {
        numVertices = vertices;
        adjList.resize(vertices);
        heuristic.resize(vertices);
    }

    void addEdge(int u, int v, int cost) {
        adjList[u].push_back({v, cost});
    }

    void setHeuristic(int node, int h) {
        heuristic[node] = h;
    }

    // A* Search from 'start' to 'goal'
    void aStarSearch(int start, int goal) {
        priority_queue<Node, vector<Node>, Compare> pq;
        vector<int> bestG(numVertices, INT_MAX);

        pq.push({start, 0, heuristic[start]});
        bestG[start] = 0;

        while (!pq.empty()) {
            Node current = pq.top();
            pq.pop();

            if (current.vertex == goal) {
                cout << "Goal reached! Optimal cost = " << current.gCost << endl;
                return;
            }

            for (auto &[neighbour, cost] : adjList[current.vertex]) {
                int newG = current.gCost + cost;
                if (newG < bestG[neighbour]) {
                    bestG[neighbour] = newG;
                    int newF = newG + heuristic[neighbour];
                    pq.push({neighbour, newG, newF});
                }
            }
        }
        cout << "Goal not reachable." << endl;
    }
};

int main() {
    // Nodes: 0 = S, 1 = A, 2 = B, 3 = G
    Graph g(4);
    g.addEdge(0, 1, 1);  // S -> A, actual cost 1
    g.addEdge(0, 2, 4);  // S -> B, actual cost 4
    g.addEdge(1, 3, 5);  // A -> G, actual cost 5
    g.addEdge(2, 3, 1);  // B -> G, actual cost 1

    g.setHeuristic(0, 3); // h(S) = 3
    g.setHeuristic(1, 0); // h(A) = 0
    g.setHeuristic(2, 1); // h(B) = 1
    g.setHeuristic(3, 0); // h(G) = 0

    g.aStarSearch(0, 3); // Start S(0), Goal G(3)
    return 0;
}
```

**Expected Output:**
```
Goal reached! Optimal cost = 5
```

This matches the hand trace exactly — unlike Greedy Best-First Search (which returned cost `6`), A\* correctly returns the true optimal cost of **5**, by properly weighing both the real cost paid (`g`) and the heuristic estimate (`h`) at every step.

### Real-Life Example 1: GPS Navigation Apps (Google Maps, Waymo, etc.)

Modern navigation systems use A\*-style algorithms extensively: `g(n)` is the actual driving distance/time already travelled, and `h(n)` is the straight-line ("as the crow flies") distance remaining to the destination. This combination lets the app rapidly skip over obviously bad roads (thanks to the heuristic) while still **guaranteeing** it finds the genuinely shortest/fastest overall route (thanks to including the real cost so far).

### Real-Life Example 2: Video Game Pathfinding (NPCs and Enemy AI)

Almost every modern video game with characters that walk intelligently around obstacles (from mobile games to AAA titles) uses A\* for pathfinding on the game map's grid or navigation mesh. The heuristic is typically the straight-line or grid distance to the target, letting characters navigate around walls and obstacles efficiently while still reaching their target via a genuinely short path, in real time, even on very large maps.

***
