# Introduction to Game Playing and Algorithms

## 1. Introduction to Game Playing (Adversarial Search)

### 1.1 What is "Game Playing" in AI?

#### Simple Meaning

**Game Playing** in Artificial Intelligence refers to a special category of search problems called **Adversarial Search**. Unlike normal search (BFS, DFS, A\*, Hill Climbing) where a single agent tries to reach a goal in a static environment, in game playing **two agents compete against each other**, and each move one player makes directly affects what the other player can do next. One agent (**MAX**) tries to **maximize** its outcome, while the other (**MIN**) tries to **minimize** MAX's outcome — hence the name **MIN-MAX** setting.

Because the opponent is actively working *against* you, the search must account for the **worst-case response** at every turn — you can't just search for "a good path," you have to search for a move that is good **even after the opponent plays their best countermove**.

**In the simplest words:** Imagine playing Tic-Tac-Toe or Chess. You don't just think "what's my best move?" — you think "if I play this, what's the *best* (worst-for-me) move my opponent can make in response? And after that, what's my best comeback?" You are planning several steps ahead, assuming your opponent always plays optimally against you.

```
GAME PLAYING — THE ADVERSARIAL IDEA
════════════════════════════════════

Level 1:                    MAX ●               (your turn)
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
Level 2:    MIN ●           MIN ●           MIN ●          (opponent's turn)
              │               │               │
              ▼               ▼               ▼
             ...             ...             ...           (deeper game tree,
                                                              MAX/MIN keep
                                                              alternating)

  MAX  ● → at Level 1, picks whichever branch MAXIMIZES the outcome for MAX
  MIN  ● → at Level 2, picks whichever branch MINIMIZES the outcome for MAX

  Unlike normal search, the environment does NOT stay still here —
  a second, opposing agent is actively choosing moves to hurt you.
```

#### Everyday Analogy

Think of a **chess match**. You never plan just your next move in isolation — you imagine "If I move my knight here, my opponent will probably take my bishop, and then I'll need to respond with..." You are mentally simulating a back-and-forth **tree of moves and countermoves**, always assuming the opponent will pick their strongest reply, not a weak one. Game-playing algorithms formalize exactly this instinct.

***

### 1.2 Why Game Playing Needs a Different Kind of Search

| Aspect | Normal Search (BFS/DFS/A\*/Hill Climbing) | Game Playing (Adversarial Search) |
| :-- | :-- | :-- |
| **Number of agents** | One agent acting alone | **Two agents**, with opposite goals |
| **Environment** | Static — doesn't fight back | **Dynamic and hostile** — opponent actively counters you |
| **Goal** | Reach a goal state / optimize a value | Choose a move that is best **assuming the worst valid response** |
| **What is searched** | A path from start to goal | A **game tree** of alternating MAX and MIN turns |
| **Success measure** | Path cost / heuristic value | **Utility value** at terminal (end) states — e.g., Win = +1, Lose = −1, Draw = 0 |

#### Why This Matters

Because you cannot control what your opponent will do, a good game-playing move is not simply "the move that looks best right now" — it is **the move that leaves you best off after your opponent responds optimally**. This is precisely what the algorithms below are built to compute.

***

### 1.3 Two Famous Game-Playing Algorithms

Game playing in AI is dominated by two classic, closely-related algorithms:

1. **Minimax Algorithm** — the foundational algorithm that explores the *entire* game tree and picks the move that guarantees the best possible outcome against a perfectly-playing opponent.
2. **Alpha-Beta Pruning** — an optimization *on top of* Minimax that skips over (prunes) branches of the game tree that can be mathematically proven to never affect the final decision, making the search much faster without changing the result.

```
MINIMAX  vs  ALPHA-BETA PRUNING — AT A GLANCE
────────────────────────────────────────────────
Minimax          →  explores EVERY node in the game tree
Alpha-Beta       →  explores the SAME tree, but skips branches
                     that can't possibly change the final answer
                     (same result as Minimax, far less work)
```

This document explains **Minimax** in detail below. Alpha-Beta Pruning builds directly on it and is covered separately.

## 2. The Minimax Algorithm

### 2.1 What is Minimax?

#### Simple Meaning

**Minimax** is a recursive **decision-making algorithm** used for two-player, turn-based, zero-sum games (one player's gain is the other's loss — e.g., Tic-Tac-Toe, Chess, Checkers). It builds a **game tree** of all possible future moves, assigns a **utility value** to each terminal (end-of-game) state, and then propagates those values back up the tree:

- At every **MAX** level (your turn), it picks the **child with the highest value**.
- At every **MIN** level (opponent's turn), it picks the **child with the lowest value**.

This "bounce" between taking the maximum and the minimum all the way up to the root is where the name **Minimax** comes from.

**In the simplest words:** You imagine every possible way the game could play out. At your opponent's turns, you assume they will pick whatever hurts you most (the minimum for you). At your own turns, you pick whatever helps you most (the maximum for you). Working backward from all the possible endings, you figure out the best move you can make **right now**.

#### Everyday Analogy

Picture a game of Tic-Tac-Toe near the end of the board. Before you place your mark, you mentally play out: "If I go here, they'll go there to block me, then I'll be forced into this square, and it'll end in a draw. But if I go over there instead, no matter what they do, I win." Minimax is simply this mental process, done exhaustively and formally for every possible sequence of moves.

***

### 2.2 How Minimax Works — Step by Step

1. Build the **game tree** from the current state, alternating **MAX** and **MIN** levels for each player's turn, down to terminal states (win/lose/draw, or a fixed search depth).
2. Assign a **utility value** to every terminal state (e.g., `+1` = MAX wins, `-1` = MIN wins, `0` = draw).
3. **Recurse back up the tree**:
   a. If the current node is a **MAX node**, its value = the **maximum** of its children's values.
   b. If the current node is a **MIN node**, its value = the **minimum** of its children's values.
4. Once values have propagated all the way to the **root**, the root's value tells you the game's outcome under optimal play — and the **child branch that produced that value** is the move MAX should actually make.

```
MINIMAX — PSEUDOCODE FLOW

   ┌───────────────────────────────┐
   │ minimax(node, isMaxTurn)      │
   └───────────────┬───────────────┘
                    │
                    ▼
        ┌───────────────────────┐   Yes
        │ node is terminal /    ├───────────► return utility(node)
        │ depth limit reached?  │
        └───────────┬───────────┘
                    │ No
                    ▼
        ┌───────────────────────┐
        │ isMaxTurn == true?    │
        └─────┬─────────────┬───┘
           Yes│              │No
              ▼              ▼
   best = -∞               best = +∞
   for each child:          for each child:
     val = minimax(child,     val = minimax(child,
                    false)                   true)
     best = max(best, val)    best = min(best, val)
              │              │
              ▼              ▼
        return best      return best
```

***

### 2.3 Worked Example — A Small Game Tree

Consider a tiny game where **MAX moves first**, then **MIN** replies, and the game ends after just those two turns. MAX has two moves (**A**, **B**); after each, MIN also has two replies, leading to **4 terminal states** with the utility values shown (higher = better for MAX).

```
MINIMAX ON A GAME TREE  (graph view — values flow UPWARD)
════════════════════════════════════════════════════════

                              MAX
                        ┌──────●──────┐
                        │    (root)   │
                    A  ╱               ╲  B
                      ╱                 ╲
                     ▼                   ▼
                  MIN●                 MIN●
                 ╱     ╲              ╱     ╲
             A1 ╱       ╲ A2      B1 ╱       ╲ B2
               ▼         ▼          ▼         ▼
              [3]       [5]        [2]       [9]   ← terminal utility values

STEP 1 — MIN nodes pick the MINIMUM of their children:
   Left MIN node   = min(3, 5) = 3
   Right MIN node  = min(2, 9) = 2

                              MAX
                        ┌──────●──────┐
                        │    (root)   │
                    A  ╱               ╲  B
                      ╱                 ╲
                     ▼                   ▼
                 MIN [3]              MIN [2]
                 ╱     ╲              ╱     ╲
               (3)     (5)          (2)     (9)

STEP 2 — MAX (root) picks the MAXIMUM of its children:
   root = max(3, 2) = 3

                        ┌──── MAX [3] ────┐
                        │    (root)       │
                    A  ╱                   ╲  B
                      ▼                     ▼
                 MIN [3]               MIN [2]
                 ╱     ╲               ╱     ╲
               (3)     (5)           (2)     (9)

RESULT: root value = 3  →  MAX should choose move "A"
   (even though "B" LOOKS tempting because of the 9, MIN would never
    let MAX reach that 9 — MIN would reply with B1 and force a 2.
    Move "A" guarantees MAX at least a 3, which is the best MAX can
    force against an opponent who always plays optimally.)
```

This is the core insight of Minimax: it never assumes the opponent will make a mistake. It always assumes MIN plays the reply that is **worst for MAX**, and picks the MAX move that is safest under that assumption.

### 2.4 C++ Implementation — Minimax on a Game Tree

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

// Represents the game tree as a fixed-depth binary tree of utility values
// at the leaves (terminal states). This mirrors the worked example above:
// depth 0 = MAX (root), depth 1 = MIN, depth 2 = terminal leaves.
vector<int> leafValues = {3, 5, 2, 9};   // terminal utility values, left to right

// minimax(depth, nodeIndex, isMaxTurn, maxDepth)
// depth      -> current depth in the tree (0 = root)
// nodeIndex  -> index of this node among nodes at this depth (used to find
//               the correct slice of leafValues for a binary tree)
// isMaxTurn  -> true if this level belongs to MAX, false if it belongs to MIN
// maxDepth   -> depth at which leaves (terminal states) are found
int minimax(int depth, int nodeIndex, bool isMaxTurn, int maxDepth) {
    // Base case: terminal state reached -> return its utility value
    if (depth == maxDepth) {
        return leafValues[nodeIndex];
    }

    if (isMaxTurn) {
        int best = INT_MIN;
        for (int i = 0; i < 2; i++) {          // binary tree -> 2 children
            int val = minimax(depth + 1, nodeIndex * 2 + i, false, maxDepth);
            best = max(best, val);              // MAX picks the highest value
        }
        return best;
    } else {
        int best = INT_MAX;
        for (int i = 0; i < 2; i++) {
            int val = minimax(depth + 1, nodeIndex * 2 + i, true, maxDepth);
            best = min(best, val);              // MIN picks the lowest value
        }
        return best;
    }
}

int main() {
    int maxDepth = 2;   // root -> MIN level -> terminal leaves
    int optimalValue = minimax(0, 0, true, maxDepth);

    cout << "Leaf (terminal) values: ";
    for (int v : leafValues) cout << v << " ";
    cout << "\n";

    cout << "Optimal value MAX can guarantee: " << optimalValue << "\n";
    return 0;
}
```

**Expected Output:**
```
Leaf (terminal) values: 3 5 2 9
Optimal value MAX can guarantee: 3
```

This trace mirrors the worked example exactly: it recurses all the way down to the terminal utility values `{3, 5, 2, 9}`, has each **MIN** node take the minimum of its two children (`min(3,5)=3` and `min(2,9)=2`), and then has the **MAX** root take the maximum of those two results (`max(3,2)=3`) — confirming that move **"A"** is the correct choice, guaranteeing MAX a value of `3` against optimal opposition.
