# Introduction to Natural Language Processing (NLP)

## 1. What is "Natural Language Processing"?

### 1.1 Simple Meaning

**Natural Language Processing (NLP)** is a branch of **Artificial Intelligence (AI)** that gives computers the ability to **read, understand, and work with human language** -- the language we speak and write every day, such as English or Hindi.

A computer, at its core, only understands **numbers**. Human language is made of **words, grammar, slang, and context**. NLP is the bridge that **converts human language into a form a computer can compute with**, and then (when needed) turns the computer's answer back into human language.

### 1.2 Everyday Analogy

Imagine a very fast but very **literal librarian** who understands **only numbered catalogue codes**. If you walk up and say, *"I would like a book about cricket,"* he has no idea what to do -- unless someone first **translates your sentence into catalogue numbers** he can search with. NLP is that translator: it takes your natural sentence and converts it, step by step, into numbers the machine can work with.

### 1.3 Why Is Human Language Hard for Computers?

| Challenge | Example | Why It Is Hard |
| :-- | :-- | :-- |
| **Ambiguity** | *"I saw a man with a telescope."* | Did **I** use the telescope, or did the **man** have it? One sentence, two meanings |
| **Context Dependence** | *"The bank was crowded."* | A river bank or a money bank? Only the surrounding context tells you |
| **Variation** | *"Cricket"*, *"cricket"*, *"CRICKET!"* | The same word can be written many different ways |
| **Informal Language** | *"That movie was sick!"* | Slang can mean the opposite of the literal word |

### 1.4 Where Is NLP Used?

| Application | What NLP Does |
| :-- | :-- |
| **Chatbots and Voice Assistants** | Understands your question and produces a reply |
| **Machine Translation** | Converts text from one language to another |
| **Sentiment Analysis** | Decides whether a review is positive or negative |
| **Spam Detection** | Reads an email's text to decide whether it is spam |
| **Search Engines** | Matches what you typed with relevant pages |
| **Text Summarization** | Shrinks a long article into a few key sentences |

## 2. The Big Picture -- From Language to Numbers

Before a model can learn anything from text, the text must travel through a short **pipeline**. This note walks through each stage in detail.

```
THE NLP PREPARATION PIPELINE

   NATURAL LANGUAGE (raw text written by a human)
              |
              v
   [ STAGE 1 ]  TEXT PROCESSING
                Clean the raw string (lowercase, remove punctuation)
              |
              v
   [ STAGE 2 ]  TOKENIZATION
                Split the cleaned text into small pieces called TOKENS
              |
              v
   [ STAGE 3 ]  TOKEN REFINEMENT
                Remove useless tokens (stop words), reduce words to
                their base form (stemming / lemmatization)
              |
              v
   [ STAGE 4 ]  NUMERICAL REPRESENTATION
                Turn tokens into numbers: vocabulary, token IDs,
                one-hot vectors, Bag of Words
              |
              v
   MATHEMATICAL FORM (numbers a machine learning model can compute with)
```

| Stage | Input | Output |
| :-- | :-- | :-- |
| **1. Text Processing** | Raw string | Clean string |
| **2. Tokenization** | Clean string | List of tokens |
| **3. Token Refinement** | List of tokens | Shorter, standardized list of tokens |
| **4. Numerical Representation** | Refined tokens | Numbers (IDs and vectors) |

***

## 3. Text Processing

### 3.1 Simple Meaning

**Text Processing** (also called **text cleaning** or **text preprocessing**) means **tidying up raw text** so that the same word is always written the same way, and useless noise is removed. Raw text is messy -- it has capital letters, punctuation, filler words, and different forms of the same word. Cleaning it first makes everything that follows simpler and more accurate.

### 3.2 Everyday Analogy

Think of **washing vegetables before cooking**. You would never throw unwashed, dirty vegetables straight into the pot. Washing them first removes dirt and makes sure every piece is in a usable state. Text processing is the "washing" step for text.

### 3.3 Common Text Processing Steps

| # | Step | What It Does | Before | After |
| :-- | :-- | :-- | :-- | :-- |
| **1** | **Lowercasing** | Converts every letter to lowercase, so `Cricket` and `cricket` are treated as the same word | `Cricket` | `cricket` |
| **2** | **Punctuation Removal** | Deletes symbols such as `, . ! ?` that would otherwise stick to words | `cricket,` | `cricket` |
| **3** | **Stop Word Removal** | Removes very common words (`i`, `and`, `my`, `the`, `is`) that carry little meaning on their own | `i love cricket` | `love cricket` |
| **4** | **Stemming or Lemmatization** | Reduces a word to its base form, so `playing`, `plays`, `played` all become `play` | `playing` | `play` |

### 3.4 Stemming vs. Lemmatization

Both aim to reduce a word to a base form, but they work differently:

| Aspect | **Stemming** | **Lemmatization** |
| :-- | :-- | :-- |
| **How It Works** | Chops off word endings using simple rules | Looks the word up in a dictionary to find its real base form (the **lemma**) |
| **Speed** | Faster | Slower |
| **Accuracy** | Can produce non-words (`studies` becomes `studi`) | Produces real words (`studies` becomes `study`) |
| **Example** | `playing` becomes `play` | `better` becomes `good` |

### 3.5 An Important Warning -- Cleaning Is Not Always Free

Not every cleaning step is safe for every task. For example, removing stop words from `"this movie is not good"` can delete the word **`not`**, leaving `"movie good"` -- which now means the **opposite** of the original. Which steps to apply depends on the problem you are solving.

## 4. Tokenization

### 4.1 Simple Meaning

**Tokenization** is the process of **splitting text into smaller pieces called tokens**. A **token** is the basic unit that an NLP system works with -- most commonly a **word**, but it can also be a sentence, a character, or part of a word.

### 4.2 Everyday Analogy

Think of a **string of beads**. The whole necklace is the sentence, and each individual bead is a token. A computer cannot handle the whole necklace at once, but it can handle one bead at a time, and count, label, and compare the beads.

### 4.3 Types of Tokenization

Using the text `"NLP is fun. I love it!"`:

| Type | How It Splits | Result |
| :-- | :-- | :-- |
| **Sentence Tokenization** | Splits into sentences | `["NLP is fun.", "I love it!"]` |
| **Word Tokenization** | Splits into words | `["NLP", "is", "fun", "I", "love", "it"]` (punctuation removed) |
| **Character Tokenization** | Splits into single characters (shown for the word `fun`) | `["f", "u", "n"]` |
| **Subword Tokenization** | Splits words into meaningful pieces (shown for `playing`) | `["play", "ing"]` |

> **Note:** Modern large language models mostly use **subword tokenization** (for example, an algorithm called Byte Pair Encoding). The exact way a word is split depends on the tokenizer. This note uses **word tokenization**, since it is the easiest to follow.

### 4.4 Why Tokenization Matters

- It turns **one long string** into a **list of individual items** that can be counted and compared.
- Every later step (stop word removal, vocabulary building, numbering) works **token by token**.
- A badly cleaned string gives bad tokens. For example, if punctuation is not removed first, `"cricket,"` and `"cricket"` would be counted as **two different tokens** even though they are the same word.

***

## 5. Converting Tokens into Numbers (The "Math" Form)

### 5.1 Why Numbers?

A machine learning model is built from **arithmetic** -- additions, multiplications, and comparisons. It cannot multiply the word `"cricket"` by a weight. So every token must finally be represented as a **number or a list of numbers (a vector)**.

### 5.2 Step A -- Build a Vocabulary

The **vocabulary** is the list of **all unique tokens** in the text, with each one given a **unique ID number** (here, numbered in order of first appearance).

```
VOCABULARY (example)

   love     ->  0
   play     ->  1
   cricket  ->  2
   friend   ->  3
```

### 5.3 Step B -- Token IDs

Replace each token in the text with its vocabulary ID. The sentence becomes a **sequence of integers**.

### 5.4 Step C -- One-Hot Encoding

Each token becomes a vector the same length as the vocabulary, filled with `0`s except for a single `1` at that token's ID position.

| Token | ID | One-Hot Vector |
| :-- | :-: | :-- |
| `love` | 0 | `[1, 0, 0, 0]` |
| `play` | 1 | `[0, 1, 0, 0]` |
| `cricket` | 2 | `[0, 0, 1, 0]` |
| `friend` | 3 | `[0, 0, 0, 1]` |

### 5.5 Step D -- Bag of Words (BoW)

Instead of one vector per token, create **one vector for the whole sentence**. Each position holds **how many times** that vocabulary word appears.

### 5.6 Comparing the Three Number Forms

| Form | Represents | Output Shape for Our Example |
| :-- | :-- | :-- |
| **Token IDs** | The sentence as a sequence of integers | 1 list of 7 numbers |
| **One-Hot Encoding** | Each token as its own vector | 7 vectors, each of length 4 |
| **Bag of Words** | The whole sentence as one count vector | 1 vector of length 4 |

## 6. Full Worked Example -- One Statement, Start to Finish

**The statement:**

```
"I love playing Cricket, and my friends love playing Cricket too!"
```

### 6.1 The Journey, Step by Step

```
RAW TEXT
   "I love playing Cricket, and my friends love playing Cricket too!"
              |
              v   Step 1: LOWERCASE
   "i love playing cricket, and my friends love playing cricket too!"
              |
              v   Step 2: REMOVE PUNCTUATION
   "i love playing cricket and my friends love playing cricket too"
              |
              v   Step 3: TOKENIZE (split into words)
   ["i", "love", "playing", "cricket", "and", "my",
    "friends", "love", "playing", "cricket", "too"]          (11 tokens)
              |
              v   Step 4: REMOVE STOP WORDS (i, and, my, too)
   ["love", "playing", "cricket", "friends",
    "love", "playing", "cricket"]                            (7 tokens)
              |
              v   Step 5: LEMMATIZE (playing -> play, friends -> friend)
   ["love", "play", "cricket", "friend",
    "love", "play", "cricket"]                               (7 tokens)
              |
              v   Step 6: BUILD VOCABULARY
   {love: 0, play: 1, cricket: 2, friend: 3}                 (4 unique tokens)
              |
              v   Step 7: CONVERT TO NUMBERS
   Token IDs      :  [0, 1, 2, 3, 0, 1, 2]
   Bag of Words   :  [2, 2, 2, 1]
```

### 6.2 What Each Step Did

| Step | Action | Why It Was Needed | Result |
| :-: | :-- | :-- | :-- |
| **1** | Lowercase | So `Cricket` and `cricket` count as the same word | All letters are lowercase |
| **2** | Remove punctuation | Without this, `cricket,` and `cricket` would be different tokens, and `too!` would not match `too` | No `,` or `!` left |
| **3** | Tokenize | Split the string into individual items | **11 tokens** |
| **4** | Remove stop words | `i`, `and`, `my`, `too` carry little meaning here | **7 tokens** |
| **5** | Lemmatize | `playing` becomes `play`, `friends` becomes `friend`, so word forms are unified | **7 tokens**, standardized |
| **6** | Build vocabulary | List the unique tokens and give each an ID | **4 unique tokens** |
| **7** | Convert to numbers | Replace tokens with IDs and counts | Numbers a model can use |

### 6.3 The Final Mathematical Form

**Token IDs** (the sentence as a sequence of numbers):

```
love  play  cricket  friend  love  play  cricket
 0     1       2        3      0     1       2

Token IDs:  [0, 1, 2, 3, 0, 1, 2]
```

**One-Hot Matrix** (7 tokens by 4 vocabulary words):

```
love     [1, 0, 0, 0]
play     [0, 1, 0, 0]
cricket  [0, 0, 1, 0]
friend   [0, 0, 0, 1]
love     [1, 0, 0, 0]
play     [0, 1, 0, 0]
cricket  [0, 0, 1, 0]
```

**Bag of Words** (the whole sentence as a single vector):

```
Vocabulary order:  [ love, play, cricket, friend ]
Counts:            [   2,     2,      2,       1  ]

Bag of Words vector:  [2, 2, 2, 1]
```

The sentence we started with -- a human statement full of capital letters, commas, and slang-free English -- is now **pure numbers**, and a machine learning model can finally compute with it.

## 7. The Same Process in Code

This simple Python program performs every step from Section 6, using only the standard library. The small `stop_words` set and `lemma_map` dictionary are deliberate simplifications; real projects use libraries such as NLTK or spaCy for full stop word lists and proper lemmatization.

```python
import string

# The raw natural-language statement
text = "I love playing Cricket, and my friends love playing Cricket too!"
print("Raw text       :", text)

# Step 1: lowercase
text = text.lower()
print("After lowercase:", text)

# Step 2: remove punctuation
text = text.translate(str.maketrans("", "", string.punctuation))
print("No punctuation :", text)

# Step 3: tokenization (word level) -- split on spaces
tokens = text.split()
print("Tokens         :", tokens, "->", len(tokens), "tokens")

# Step 4: stop word removal (a deliberately small list)
stop_words = {"i", "and", "my", "too", "the", "a", "is", "are", "in"}
tokens = [t for t in tokens if t not in stop_words]
print("No stop words  :", tokens, "->", len(tokens), "tokens")

# Step 5: lemmatization (a tiny dictionary standing in for a real lemmatizer)
lemma_map = {"playing": "play", "friends": "friend"}
tokens = [lemma_map.get(t, t) for t in tokens]
print("Lemmatized     :", tokens)

# Step 6: build the vocabulary (unique token -> ID, in order of first appearance)
vocab = {}
for t in tokens:
    if t not in vocab:
        vocab[t] = len(vocab)
print("Vocabulary     :", vocab)

# Step 7a: token IDs
token_ids = [vocab[t] for t in tokens]
print("Token IDs      :", token_ids)

# Step 7b: one-hot vectors
print("One-hot vectors:")
for t in tokens:
    vec = [0] * len(vocab)
    vec[vocab[t]] = 1
    print("  ", t.ljust(8), vec)

# Step 7c: bag of words
bow = [0] * len(vocab)
for t in tokens:
    bow[vocab[t]] += 1
print("Bag of Words   :", bow)
```

**Output:**

```
Raw text       : I love playing Cricket, and my friends love playing Cricket too!
After lowercase: i love playing cricket, and my friends love playing cricket too!
No punctuation : i love playing cricket and my friends love playing cricket too
Tokens         : ['i', 'love', 'playing', 'cricket', 'and', 'my', 'friends', 'love', 'playing', 'cricket', 'too'] -> 11 tokens
No stop words  : ['love', 'playing', 'cricket', 'friends', 'love', 'playing', 'cricket'] -> 7 tokens
Lemmatized     : ['love', 'play', 'cricket', 'friend', 'love', 'play', 'cricket']
Vocabulary     : {'love': 0, 'play': 1, 'cricket': 2, 'friend': 3}
Token IDs      : [0, 1, 2, 3, 0, 1, 2]
One-hot vectors:
   love     [1, 0, 0, 0]
   play     [0, 1, 0, 0]
   cricket  [0, 0, 1, 0]
   friend   [0, 0, 0, 1]
   love     [1, 0, 0, 0]
   play     [0, 1, 0, 0]
   cricket  [0, 0, 1, 0]
Bag of Words   : [2, 2, 2, 1]
```

This output matches the hand-worked example in Section 6 exactly.

## 8. Limitations of This Simple Numeric Form

The number forms in Section 5 are the foundation of NLP, but they have real weaknesses:

| Limitation | Explanation | Example |
| :-- | :-- | :-- |
| **Word order is lost (Bag of Words)** | Only counts are kept, not position | `"dog bites man"` and `"man bites dog"` give the **same** Bag of Words vector, though the meanings are very different |
| **No sense of meaning (One-Hot)** | Every word is equally "far" from every other word | `good` and `great` are as unrelated as `good` and `banana` |
| **Large and mostly empty vectors** | A real vocabulary can have tens of thousands of words, so each vector is almost all zeros | A 50,000-word vocabulary needs 50,000 numbers per token |

These weaknesses are exactly why more advanced techniques, such as **word embeddings**, were developed -- they represent each word as a short list of numbers that captures **meaning**, so similar words end up with similar numbers.

## 9. Summary

| Concept | One-Line Summary |
| :-- | :-- |
| **NLP** | The branch of AI that lets computers read, understand, and work with human language |
| **Why It Is Hard** | Human language is ambiguous, context-dependent, and full of variation |
| **Text Processing** | Cleaning raw text: lowercasing, punctuation removal, stop word removal, stemming or lemmatization |
| **Stemming vs. Lemmatization** | Stemming chops endings by rule; lemmatization uses a dictionary to find the real base word |
| **Tokenization** | Splitting text into small pieces (tokens) -- usually words, but also sentences, characters, or subwords |
| **Vocabulary** | The list of all unique tokens, each with a unique ID |
| **Token IDs** | The sentence rewritten as a sequence of integers |
| **One-Hot Encoding** | Each token becomes a vector with a single `1` at its ID position |
| **Bag of Words** | The whole sentence becomes one vector of word counts |
| **The Pipeline** | Natural language -> Text Processing -> Tokenization -> Token Refinement -> Numbers |
| **Key Limitation** | These simple forms lose word order and meaning, which is why embeddings were invented |
