# Decision Tree
## 1. Basic Terminology Used in Decision Trees

### 1.1 Terms and Meanings

| Term | Meaning |
| :-- | :-- |
| **Root Node** | The **starting point** of the decision tree. It represents the **entire dataset**, which is then divided into **smaller, more homogeneous groups** |
| **Splitting** | The process of **dividing a node into two or more sub-nodes** based on a certain condition that **maximizes the separation of the classes** |
| **Decision Node** | The nodes **where the splits happen**. A decision node can lead to **further decision nodes** or to a **leaf node** |
| **Leaf (Terminal) Node** | The **final nodes** that do **not split further**. Each leaf node represents a **classification or decision outcome** |
| **Pruning** | A technique used to **reduce the size** of a decision tree. It involves **removing nodes that have little impact** on the decision process, to **prevent overfitting** |
| **Branch / Sub-tree** | A section of the decision tree that represents **a part of the whole decision process** |
| **Parent and Child Nodes** | In any split, the **original node** is called the **parent node**, and the **resulting sub-nodes** are called **child nodes** |

### 1.2 Structure of a Decision Tree

The diagram below shows how these terms fit together in one tree.

```
                       ┌───────────────┐
                       │ Decision Node │  ──►  ROOT NODE
                       └───────┬───────┘
              ┌────────────────┴────────────────┐
╭┄ Sub-Tree ┄┄▼┄┄┄┄┄┄┄┄┄┄┄┄┄┄╮                  ▼
┆     ┌───────────────┐      ┆          ┌───────────────┐
┆     │ Decision Node │      ┆          │ Decision Node │
┆     └───────┬───────┘      ┆          └───────┬───────┘
┆      ┌──────┴───────┐      ┆       ┌──────────┴──────────┐
┆      ▼              ▼      ┆       ▼                     ▼
┆╭───────────╮  ╭───────────╮┆ ╭───────────╮       ┌───────────────┐
┆│ Leaf Node │  │ Leaf Node │┆ │ Leaf Node │       │ Decision Node │
┆╰───────────╯  ╰───────────╯┆ ╰───────────╯       └───────┬───────┘
╰┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄╯                      ┌──────┴───────┐
                                                    ▼              ▼
                                              ╭───────────╮  ╭───────────╮
                                              │ Leaf Node │  │ Leaf Node │
                                              ╰───────────╯  ╰───────────╯
```

**Diagram key:** square boxes are **Decision Nodes**, rounded boxes are **Leaf Nodes**, and the dashed area is a **Sub-Tree**.

| Part of the Diagram | Term |
| :-- | :-- |
| The **top Decision Node** (marked *ROOT NODE*) | **Root Node** |
| Every box that **splits into further nodes**  | **Decision Node** |
| The **rounded boxes** at the ends of the branches | **Leaf (Terminal) Node** |
| The **dashed area** on the left: a Decision Node together with its two Leaf Nodes | **Branch / Sub-Tree** |
| Any node and the nodes directly below it after a split | **Parent and Child Nodes** |

**How to read the diagram:**

| Step | What Happens |
| :-- | :-- |
| **(1)** | The **Root Node** splits into **two Decision Nodes** |
| **(2)** | The **left Decision Node** splits into **two Leaf Nodes**. This part is the **Sub-Tree** |
| **(3)** | The **right Decision Node** splits into **one Leaf Node** and **one more Decision Node** |
| **(4)** | That last **Decision Node** splits into **two Leaf Nodes** |

## 2. Why Decision Trees Are Popular

**Decision trees** are a popular tool for **decision-making and prediction** for several reasons.

| Reason | Key Idea |
| :-- | :-- |
| **(1) Clear Visualization** | Easy to visualize, so the **decision-making steps can be followed clearly** |
| **(2) Low Data Preparation** | Needs **minimal data preprocessing** |
| **(3) Efficient and Scalable** | **Prediction costs grow logarithmically** with data size |
| **(4) Flexible Data Handling** | Handles **both numerical and categorical data** |
| **(5) Robust to Assumptions** | Works well **even when data assumptions are not met** |

***

### 2.1 Clear Visualization

| Item | Details |
| :-- | :-- |
| **Meaning** | Decision trees are **easily visualized**, allowing users to **follow the decision-making steps clearly** |
| **Example** | A **bank** might use a decision tree to determine **creditworthiness** based on criteria like **income, debt, and credit history** |

```
                  ┌─────────────────┐
                  │ Credit History  │
                  └────────┬────────┘
          ┌────────────────┴─────────────────┐
         Bad                               Good
          ▼                                  ▼
╭───────────────────╮                ┌───────────────┐
│ Not Creditworthy  │                │ Check Income  │
╰───────────────────╯                └───────┬───────┘
                               ┌─────────────┴──────────────┐
                             High                      Low/Medium
                               ▼                            ▼
                       ╭───────────────╮             ┌─────────────┐
                       │ Creditworthy  │             │ Check Debt  │
                       ╰───────────────╯             └──────┬──────┘
                                                  ┌─────────┴──────────┐
                                                 Low                 High
                                                  ▼                    ▼
                                          ╭───────────────╮  ╭───────────────────╮
                                          │ Creditworthy  │  │ Not Creditworthy  │
                                          ╰───────────────╯  ╰───────────────────╯
```

| Path | Outcome |
| :-- | :-- |
| Credit History = **Bad** | **Not Creditworthy** |
| Credit History = **Good** → Income = **High** | **Creditworthy** |
| Credit History = **Good** → Income = **Low/Medium** → Debt = **Low** | **Creditworthy** |
| Credit History = **Good** → Income = **Low/Medium** → Debt = **High** | **Not Creditworthy** |

### 2.2 Low Data Preparation

| Item | Details |
| :-- | :-- |
| **Meaning** | Decision trees require **minimal data preprocessing**, such as **not needing to normalize data** |
| **Example** | A **marketing team** using **customer demographic data directly** to predict **purchasing behaviors** |

```
                ┌─────┐
                │ Age │
                └──┬──┘
       ┌───────────┴────────────┐
     Young               Middle-aged/Old
       ▼                        ▼
╭─────────────╮         ┌───────────────┐
│ Not Buying  │         │ Check Income  │
╰─────────────╯         └───────┬───────┘
                      ┌─────────┴─────────┐
                    High             Low/Medium
                      ▼                   ▼
                 ╭─────────╮     ┌─────────────────┐
                 │ Buying  │     │ Check Location  │
                 ╰─────────╯     └────────┬────────┘
                                   ┌──────┴───────┐
                                 Urban     Suburban/Rural
                                   ▼              ▼
                              ╭─────────╮  ╭─────────────╮
                              │ Buying  │  │ Not Buying  │
                              ╰─────────╯  ╰─────────────╯
```

| Path | Outcome |
| :-- | :-- |
| Age = **Young** | **Not Buying** |
| Age = **Middle-aged/Old** → Income = **High** | **Buying** |
| Age = **Middle-aged/Old** → Income = **Low/Medium** → Location = **Urban** | **Buying** |
| Age = **Middle-aged/Old** → Income = **Low/Medium** → Location = **Suburban/Rural** | **Not Buying** |

### 2.3 Efficient and Scalable

| Item | Details |
| :-- | :-- |
| **Meaning** | The model is **efficient**, with **prediction costs growing logarithmically with data size** |
| **Example** | An **online retailer** could use a decision tree to handle **millions of customer transactions efficiently** |

```
              ┌─────────────────────┐
              │ Transaction Amount  │
              └──────────┬──────────┘
        ┌────────────────┴─────────────────┐
       Low                            Medium/High
        ▼                                  ▼
╭───────────────╮              ┌───────────────────────┐
│ Low Priority  │              │ Check Customer Status │
╰───────────────╯              └───────────┬───────────┘
                            ┌──────────────┴──────────────┐
                           New                        Returning
                            ▼                             ▼
                   ╭─────────────────╮     ┌─────────────────────────────┐
                   │ Medium Priority │     │ Check Transaction Frequency │
                   ╰─────────────────╯     └──────────────┬──────────────┘
                                                ┌─────────┴─────────┐
                                              High                 Low
                                                ▼                   ▼
                                        ╭───────────────╮  ╭─────────────────╮
                                        │ High Priority │  │ Medium Priority │
                                        ╰───────────────╯  ╰─────────────────╯
```

| Path | Outcome |
| :-- | :-- |
| Transaction Amount = **Low** | **Low Priority** |
| Transaction Amount = **Medium/High** → Customer Status = **New** | **Medium Priority** |
| Transaction Amount = **Medium/High** → Customer Status = **Returning** → Transaction Frequency = **High** | **High Priority** |
| Transaction Amount = **Medium/High** → Customer Status = **Returning** → Transaction Frequency = **Low** | **Medium Priority** |

***

### 2.4 Flexible Data Handling

| Item | Details |
| :-- | :-- |
| **Meaning** | Capable of processing **both numerical and categorical data**, making them suitable for **diverse scenarios** |
| **Example** | A **healthcare provider** could use decision trees to analyze patient data that includes both **numerical** (e.g., blood pressure readings) and **categorical** (e.g., symptom presence) data |

```
        ┌─────────────────┐
        │ Blood Pressure  │
        └────────┬────────┘
      ┌──────────┴──────────┐
   <= 120                 > 120
      ▼                     ▼
╭───────────╮      ┌─────────────────┐
│ Low Risk  │      │ Check Symptoms  │
╰───────────╯      └────────┬────────┘
                     ┌──────┴───────┐
                    Yes            No
                     ▼              ▼
               ╭───────────╮  ╭───────────╮
               │ High Risk │  │ Low Risk  │
               ╰───────────╯  ╰───────────╯
```

| Path | Outcome |
| :-- | :-- |
| Blood Pressure `<= 120` | **Low Risk** |
| Blood Pressure `> 120` → Symptoms = **Yes** | **High Risk** |
| Blood Pressure `> 120` → Symptoms = **No** | **Low Risk** |

| Data Used in the Tree | Type |
| :-- | :-- |
| **Blood Pressure** (readings) | **Numerical** |
| **Symptoms** (presence: Yes / No) | **Categorical** |

***

### 2.5 Robust to Assumptions

| Item | Details |
| :-- | :-- |
| **Meaning** | Decision trees work well **even when data assumptions are not met**, such as **non-linearity** or **non-normal distributions** |
| **Example** | Their use in **environmental studies**, where data often **defies typical statistical assumptions** |

```
         ┌─────────────────┐
         │ Pollution Level │
         └────────┬────────┘
      ┌───────────┴───────────┐
     Low                    High
      ▼                       ▼
╭───────────╮       ┌───────────────────┐
│ Low Risk  │       │ Check Temperature │
╰───────────╯       └─────────┬─────────┘
                      ┌───────┴───────┐
                    <= 35           > 35
                      ▼               ▼
               ╭─────────────╮  ╭───────────╮
               │ Medium Risk │  │ High Risk │
               ╰─────────────╯  ╰───────────╯
```

| Path | Outcome |
| :-- | :-- |
| Pollution Level = **Low** | **Low Risk** |
| Pollution Level = **High** → Temperature = `<= 35` | **Medium Risk** |
| Pollution Level = **High** → Temperature = `> 35` | **High Risk** |
