# QuerySets and ORM Methods


---

## 1. Introduction to QuerySets

**Definition:** A QuerySet is a collection of database queries represented as a Python object, used to retrieve, filter, and manipulate objects from the database; it represents a list of objects from a given model, without necessarily having executed the actual database query yet.

### 1.1 Key Characteristics of QuerySets

- **Lazy evaluation:** a QuerySet does not hit the database the moment it is written; it only executes the actual SQL query when the data is actually needed (for example, when looped over, printed, or converted to a list).
- **Iterable:** a QuerySet behaves like a list — it can be looped over using a `for` loop, exactly as seen with `Student.objects.all()` in templates.
- **Chainable:** multiple QuerySet methods can be called one after another, each refining the result further, before the query is finally executed.

**Important Definition (Quotable):** Django QuerySets are lazily evaluated, meaning the database is not actually queried until the QuerySet is evaluated — for example, by iterating over it, slicing it, or calling functions like list() on it; this allows multiple filters to be chained efficiently into a single SQL query.

---

## 2. The objects Manager

**Definition:** The `objects` attribute is a Manager automatically added by Django to every model; it is the primary interface through which database query operations are performed for that model.

### 2.1 Key Points

- Every Django model automatically gets `objects` as its default manager, unless a custom manager is explicitly defined.
- All QuerySet methods (`all()`, `filter()`, `get()`, `create()`, etc.) are called through this manager.
- Syntax pattern: `ModelName.objects.method()`

**Example:**
```python
Student.objects.all()
```

---

## 3. Basic CRUD Operations

CRUD stands for Create, Read, Update, Delete — the four fundamental database operations. This section covers Create and Read; Update and Delete are covered in Section 7.

### 3.1 create()

**Definition:** `create()` is a QuerySet method that builds a new model instance and saves it to the database in a single step.

```python
Student.objects.create(name="Amit Sharma", age=20, email="amit@example.com")
```

```python
s = Student(name="Amit Sharma", age=20, email="amit@example.com")
s.save()
```
Both approaches insert a new row, but `create()` does it in one line.

### 3.2 all()

**Definition:** `all()` returns a QuerySet containing every record of that model currently stored in the database.

```python
Student.objects.all()
```

### 3.3 get()

**Definition:** `get()` returns a single object matching the given lookup parameters; it raises an error if no object matches, and a different error if more than one object matches.

```python
Student.objects.get(id=1)
Student.objects.get(email="amit@example.com")
```

| Situation | Result |
|---|---|
| Exactly one match found | Returns that single object |
| No match found | Raises `Student.DoesNotExist` |
| More than one match found | Raises `Student.MultipleObjectsReturned` |

**Important Definition (Quotable):** Unlike filter(), which always returns a QuerySet (even if empty or containing multiple items), get() is designed to return exactly one object, and will raise an exception if that expectation is not met — this is why get() is typically used with a field guaranteed to be unique, such as a primary key.

**Exam Tip:** This distinction between `get()` and `filter()` is one of the most frequently tested points in this chapter — be ready to explain both the syntax difference and the behavioral difference (exception vs empty QuerySet).

## 4. Filtering with filter() and exclude()

### 4.1 filter()

**Definition:** `filter()` returns a new QuerySet containing only the objects that match the given lookup parameters; unlike get(), it always returns a QuerySet, which may contain zero, one, or many objects.

```python
Student.objects.filter(age=20)
```

### 4.2 exclude()

**Definition:** `exclude()` returns a new QuerySet containing all objects that do NOT match the given lookup parameters — it is the logical opposite of filter().

```python
Student.objects.exclude(age=20)
```

### 4.3 Comparison Table

| Aspect | get() | filter() | exclude() |
|---|---|---|---|
| Returns | Single object | QuerySet (possibly empty) | QuerySet (possibly empty) |
| If no match | Raises DoesNotExist | Returns empty QuerySet | Returns full QuerySet if nothing excluded |
| If multiple match | Raises MultipleObjectsReturned | Returns all matches | Returns all non-matches |
| Typical use case | Fetching one record by unique field (like id) | Fetching a subset of records | Fetching everything except a subset |

## 5. Field Lookups

**Definition:** Field lookups are special suffixes, written using a double underscore, appended to a field name inside filter()/exclude()/get(), that specify the type of SQL comparison to perform (such as greater than, contains, or case-insensitive match).

### 5.1 Common Field Lookups

| Lookup | Meaning | Example |
|---|---|---|
| `__exact` | Exact match (this is the default if no lookup is specified) | `filter(name__exact="Amit Sharma")` |
| `__iexact` | Case-insensitive exact match | `filter(name__iexact="amit sharma")` |
| `__contains` | Field contains the given substring (case-sensitive) | `filter(name__contains="Sharma")` |
| `__icontains` | Field contains the given substring (case-insensitive) | `filter(name__icontains="sharma")` |
| `__gt` | Greater than | `filter(age__gt=18)` |
| `__gte` | Greater than or equal to | `filter(age__gte=18)` |
| `__lt` | Less than | `filter(age__lt=25)` |
| `__lte` | Less than or equal to | `filter(age__lte=25)` |
| `__in` | Value is in a given list | `filter(age__in=[18, 20, 22])` |
| `__startswith` | Field starts with the given string | `filter(name__startswith="A")` |
| `__endswith` | Field ends with the given string | `filter(email__endswith="@gmail.com")` |
| `__isnull` | Field is NULL (True) or not NULL (False) | `filter(address__isnull=True)` |

**Important Definition (Quotable):** A field lookup is written as fieldname__lookuptype (using a double underscore as a separator), and Django's ORM translates it into the appropriate SQL WHERE clause condition, such as >, LIKE, or IS NULL.

**Exam Tip:** Field lookups are a very high-yield topic — expect direct questions asking to write the correct lookup for a given scenario (e.g., "write a query to find all students older than 20").

## 6. order_by()

**Definition:** `order_by()` returns a new QuerySet with the results sorted according to the given field(s).

### 6.1 Syntax

```python
Student.objects.order_by('name')          # Ascending order
Student.objects.order_by('-age')           # Descending order (minus sign)
Student.objects.order_by('age', 'name')    # Multiple fields — sorts by age first, then name
```

### 6.2 Relationship With Meta.ordering

- If a model's `Meta` class already defines `ordering`, that becomes the default order for all QuerySets on that model.
- Calling `.order_by()` explicitly on a QuerySet overrides the Meta-level default ordering for that specific query.

## 7. update() and delete()

### 7.1 update()

**Definition:** `update()` is a QuerySet method that modifies all objects matching the current QuerySet directly in the database, in a single SQL UPDATE statement, without needing to load each object into Python individually.

```python
Student.objects.filter(age=18).update(age=19)
```

```python
s = Student.objects.get(id=1)
s.age = 21
s.save()
```

### 7.2 delete()

**Definition:** `delete()` removes all objects matching the current QuerySet from the database, in a single operation.

```python
Student.objects.filter(age__lt=18).delete()
```

---

## 8. count() and exists()

### 8.1 count()

**Definition:** `count()` returns the number of objects matching the current QuerySet, as an integer, without loading the actual objects into memory.

```python
Student.objects.count()
Student.objects.filter(age=20).count()
```

### 8.2 exists()

**Definition:** `exists()` returns True if the QuerySet contains at least one matching object, and False otherwise, without loading the actual objects.

```python
Student.objects.filter(email="amit@example.com").exists()
```

## 9. Chaining QuerySets

**Definition:** Chaining refers to calling multiple QuerySet methods one after another, where each method returns a new QuerySet that the next method can be called on; because of lazy evaluation, the actual database query is only executed once, at the end of the chain.

### 9.1 Example

```python
Student.objects.filter(age__gte=18).exclude(name__startswith="Z").order_by('name')
```

**Explain the chain step by step:**
1. `filter(age__gte=18)` — keep only students aged 18 or above.
2. `exclude(name__startswith="Z")` — from that result, remove any student whose name starts with "Z".
3. `order_by('name')` — sort the final result alphabetically by name.

## 10. Introduction to Aggregation

**Definition:** Aggregation refers to performing a calculation across a set of values from multiple rows (such as sum, average, count, minimum, or maximum) and returning a single summary result, using Django's `aggregate()` function.

### 10.1 aggregate()

```python
from django.db.models import Avg, Count, Max, Min, Sum

Student.objects.aggregate(Avg('age'))
Student.objects.aggregate(Max('age'), Min('age'))
```

**Explain:** `aggregate()` returns a dictionary with the calculated result, applied across the entire QuerySet — for example, `{'age__avg': 20.5}`.

### 10.2 annotate() (Conceptual Introduction)

**Definition:** `annotate()` is similar to aggregate(), but instead of returning a single summary value for the whole QuerySet, it calculates a value for each object in the QuerySet and attaches it as an extra field to each result.

**Conceptual example (relationships needed for a full working example, covered later):**
```python
# Conceptually: count how many students each department has
Department.objects.annotate(student_count=Count('student'))
```
