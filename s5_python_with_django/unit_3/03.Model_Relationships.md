# Model Relationships (OneToOne, ForeignKey, ManyToMany)

---

## 1. Introduction to Model Relationships

**Definition:** A model relationship is a connection defined between two Django models, representing how records in one database table relate to records in another table, mirroring the concept of relationships in relational database design.

### 1.1 Why Relationships Are Needed

- Real-world data is rarely isolated — a student belongs to a department, an order belongs to a customer, a post has many comments.
- Without relationships, related data would need to be duplicated across tables, leading to redundancy and inconsistency.
- Django provides three field types to represent the three fundamental types of relationships found in relational database design.

### 1.2 The Three Types of Relationships

| Relationship Type | Django Field | Real-World Example |
|---|---|---|
| One-to-One | `OneToOneField` | A Student has exactly one StudentProfile |
| One-to-Many (Many-to-One) | `ForeignKey` | A Department has many Students, each Student belongs to one Department |
| Many-to-Many | `ManyToManyField` | A Student can enroll in many Courses, each Course can have many Students |

**Important Note for Exam:** All three relationship fields are defined on the model, but they translate differently at the database level — OneToOneField and ForeignKey both use a foreign key column, while ManyToManyField creates a separate, hidden "junction table" behind the scenes to store the relationships.

---

## 2. OneToOneField

**Definition:** OneToOneField is used to create a relationship where each record in one model corresponds to exactly one record in another model, and vice versa.

### 2.1 Use Case

A common real-world use case is extending Django's built-in User model with additional profile information, without modifying the User model itself.

### 2.2 Syntax

```python
from django.db import models

class StudentProfile(models.Model):
    student = models.OneToOneField(Student, on_delete=models.CASCADE)
    bio = models.TextField(blank=True)
    profile_picture = models.CharField(max_length=200, blank=True)

    def __str__(self):
        return f"Profile of {self.student.name}"
```

**Explanation:**
- The `student` field creates a one-to-one link between `StudentProfile` and `Student`.
- Every `StudentProfile` must be linked to exactly one `Student`, and Django enforces that no two `StudentProfile` records can point to the same `Student` — this uniqueness is automatically applied at the database level.

### 2.3 Accessing the Relationship

```python
profile = StudentProfile.objects.get(student=some_student)
print(profile.student.name)

# Reverse access — from Student to its Profile
student.studentprofile.bio
```

**Important Definition :** OneToOneField behaves like a ForeignKey with an added uniqueness constraint — it ensures that each related object on the other side can be linked to at most one object of the current model, enforcing a strict one-to-one correspondence between the two tables.

---

## 3. ForeignKey

**Definition:** ForeignKey is used to create a one-to-many relationship, where one record in the related model can be associated with many records in the current model, but each record in the current model relates to only one record in the related model.

### 3.1 Use Case

A Department has many Students; each Student belongs to exactly one Department.

### 3.2 Syntax

```python
class Department(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name


class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField(default=18)
    email = models.EmailField(unique=True)
    department = models.ForeignKey(Department, on_delete=models.CASCADE, related_name='students')

    def __str__(self):
        return self.name
```

**Explanation:** The ForeignKey field is placed on the "many" side of the relationship — here, on `Student`, since many students can belong to one department.

**Important Note for Exam:** A very common exam question is "on which model should the ForeignKey be placed?" — the answer is always on the model representing the "many" side of the relationship.

---

## 4. related_name

**Definition:** `related_name` is an optional argument on ForeignKey (and ManyToManyField/OneToOneField) that defines the name used to access the reverse relationship — that is, how to query from the related model back to the model containing the ForeignKey.

### 4.1 Without related_name (Default Behavior)

If `related_name` is not specified, Django automatically creates a reverse accessor named `<modelname>_set`.

```python
department.student_set.all()
```

### 4.2 With related_name

```python
department = models.ForeignKey(Department, on_delete=models.CASCADE, related_name='students')
```

```python
department.students.all()
```

**Explanation:** `related_name='students'` replaces the default, clunky `student_set` with a clean, readable `students` attribute on the `Department` side.

**Important Definition:** related_name customizes the name of the reverse relation from the related object back to the model defining the ForeignKey; without it, Django falls back to the default convention of appending _set to the lowercase model name.

---

## 5. on_delete Options

**Definition:** `on_delete` is a compulsory argument on ForeignKey (and OneToOneField) that specifies what should happen to the records in the current model when the related object they point to is deleted.

### 5.1 Common on_delete Options

| Option | Behavior |
|---|---|
| `models.CASCADE` | When the related object is deleted, all objects referencing it are also deleted |
| `models.PROTECT` | Prevents deletion of the related object if any object still references it (raises an error) |
| `models.SET_NULL` | Sets the foreign key field to NULL when the related object is deleted (requires null=True on the field) |
| `models.SET_DEFAULT` | Sets the foreign key field to a specified default value when the related object is deleted |
| `models.DO_NOTHING` | Takes no action at the Django level (can leave the database in an inconsistent state; rarely used without extra database-level handling) |

### 5.2 Example

```python
department = models.ForeignKey(Department, on_delete=models.CASCADE, related_name='students')
```

**Explanation:** If a `Department` is deleted, every `Student` linked to it via CASCADE will also be deleted automatically.

## 6. Querying Related Objects (Forward and Reverse)

### 6.1 Forward Query (From the "Many" Side to the "One" Side)

Going from a `Student` to its `Department` — this uses the field name directly, since the ForeignKey is defined on `Student`.

```python
student = Student.objects.get(id=1)
print(student.department.name)
```

### 6.2 Reverse Query (From the "One" Side to the "Many" Side)

Going from a `Department` to all its `Student` records — this uses the `related_name` (or the default `_set` if none was given).

```python
department = Department.objects.get(id=1)
department.students.all()
```

### 6.3 Filtering Across a Relationship (Double Underscore Syntax)

Django's ORM allows filtering across relationships using the same double-underscore lookup syntax, but applied to a related field name instead of a lookup type.

```python
# All students belonging to a department named "Computer Science"
Student.objects.filter(department__name="Computer Science")
```

**Important Definition:** Django's ORM allows traversing relationships in filter() by chaining the related field name with double underscores, effectively allowing a single Python query to perform what would otherwise require a SQL JOIN.

### 6.4 Comparison Table — Forward vs Reverse

| Aspect | Forward Query | Reverse Query |
|---|---|---|
| Direction | From the model containing the ForeignKey, to the related model | From the related model, back to the model containing the ForeignKey |
| Syntax | `student.department` | `department.students.all()` (or `.student_set.all()` if no related_name) |
| Returns | A single related object | A QuerySet of related objects |

## 7. ManyToManyField

**Definition:** ManyToManyField is used to create a relationship where multiple records of one model can be associated with multiple records of another model, in both directions.

### 7.1 Use Case

A Student can enroll in many Courses; each Course can have many Students enrolled.

### 7.2 Syntax

```python
class Course(models.Model):
    title = models.CharField(max_length=100)

    def __str__(self):
        return self.title


class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField(default=18)
    email = models.EmailField(unique=True)
    department = models.ForeignKey(Department, on_delete=models.CASCADE, related_name='students')
    courses = models.ManyToManyField(Course, related_name='students')

    def __str__(self):
        return self.name
```

**Explanation:** Unlike ForeignKey, ManyToManyField does not need `on_delete`, because there is no single "owning" row that gets deleted-through — Django manages the relationship using a separate junction table behind the scenes, automatically created during migration.

---

## 8. Adding and Removing Related Objects

Unlike ForeignKey (where a single related object is simply assigned), ManyToMany relationships require special methods to manage the set of related objects, since there can be many on both sides.

### 8.1 add()

**Definition:** `add()` adds one or more objects to a ManyToMany relationship, without removing any existing related objects.

```python
student = Student.objects.get(id=1)
course = Course.objects.get(id=1)
student.courses.add(course)

# Adding multiple at once
student.courses.add(course1, course2)
```

### 8.2 remove()

**Definition:** `remove()` removes one or more specific objects from a ManyToMany relationship, without affecting other related objects.

```python
student.courses.remove(course)
```

### 8.3 set()

**Definition:** `set()` replaces the entire set of related objects in a ManyToMany relationship with the given list, removing any previous associations not included in the new list.

```python
student.courses.set([course1, course2, course3])
```

### 8.4 clear()

**Definition:** `clear()` removes all related objects from a ManyToMany relationship, leaving no associations.

```python
student.courses.clear()
```

### 8.5 Comparison Table

| Method | Effect |
|---|---|
| `add()` | Adds given object(s), keeps existing ones |
| `remove()` | Removes given object(s) only |
| `set()` | Replaces the entire relationship set with the given list |
| `clear()` | Removes all related objects |

### 8.6 Querying a ManyToMany Relationship

```python
# Forward — all courses a student is enrolled in
student.courses.all()

# Reverse — all students enrolled in a course
course.students.all()
```

## 9. Hands-On Relationship-Building Exercise

This section ties the three relationship types together in one practical flow, building on the same `Student` model used throughout Unit 3.

### 9.1 Step 1: Define All Models Together

```python
from django.db import models

class Department(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name


class Course(models.Model):
    title = models.CharField(max_length=100)

    def __str__(self):
        return self.title


class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField(default=18)
    email = models.EmailField(unique=True)
    department = models.ForeignKey(Department, on_delete=models.CASCADE, related_name='students')
    courses = models.ManyToManyField(Course, related_name='students')

    class Meta:
        ordering = ['name']

    def __str__(self):
        return self.name


class StudentProfile(models.Model):
    student = models.OneToOneField(Student, on_delete=models.CASCADE)
    bio = models.TextField(blank=True)

    def __str__(self):
        return f"Profile of {self.student.name}"
```

### 9.2 Step 2: Run Migrations

```bash
python manage.py makemigrations
python manage.py migrate
```

### 9.3 Step 3: Create Data in the Shell

```python
from students.models import Department, Course, Student, StudentProfile

# Create a department
cse = Department.objects.create(name="Computer Science")

# Create courses
python_course = Course.objects.create(title="Python Programming")
django_course = Course.objects.create(title="Django Web Development")

# Create a student linked to the department (ForeignKey)
amit = Student.objects.create(name="Amit Sharma", age=20, email="amit@example.com", department=cse)

# Add courses to the student (ManyToMany)
amit.courses.add(python_course, django_course)

# Create a one-to-one profile for the student
StudentProfile.objects.create(student=amit, bio="Enthusiastic about backend development.")
```

### 9.4 Step 4: Query the Relationships

```python
# Forward ForeignKey — student's department
amit.department.name

# Reverse ForeignKey — all students in a department
cse.students.all()

# ManyToMany — courses this student takes
amit.courses.all()

# Reverse ManyToMany — students in a course
python_course.students.all()

# OneToOne — student's profile
amit.studentprofile.bio
```
